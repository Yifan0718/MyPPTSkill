# 本地默认交付标准

这些默认规则适用于本 Skill 的所有制作、编辑与测试任务。它们优先于上游模板说明中的“不改排版”“保持原字号”“轻微超框可以接受”和“渲染可选”。用户当前任务另有明确要求时，以当前要求为准。不得把一次测试稿的页数、图表数或模拟数据固化为以后任务的默认内容。

## 制作前需求确认

### 页数约束与合理拆页

- 禁止仅为满足字号、留白或版面验收，将具有完整逻辑关系且能够合理共页展示的内容机械拆成多页。不得添加空洞封面式过渡页、重复摘要、无意义章节页或一页一句话来稀释信息密度。
- 拆页必须有真实收益：自然的论证阶段、明确的子问题、过大的数据规模、需要分别讲解的技术结构或明显的可读性改善。拆分前优先调整分栏、图表布局、列宽、段落及已授权的字号；在工作记录中说明拆分收益，不把制作理由写进 PPT。
- 用户指定页数时，优先在给定篇幅内优化信息组织，不能擅自增页。确实无法兼顾必要内容与可读性，且用户没有设定硬性上限时，先说明具体需要增加哪些内容页及数量，询问是否允许；等待答复期间不得先按更多页交付。
- 用户明确“最多/不得超过 N 页”时严格不超过；给定页数范围也在范围内安排，不默认突破上界。需要调整时应在既有上限内重组或询问内容优先级，不能以排版困难为由自动放宽。只有用户主动明确修改页数约束后才更新上限。
- 封面、目录、章节页、附录、备用页及隐藏页均计入交付总页数，除非用户明确给出其他计数口径；不得通过改页名、隐藏页面或把内容转成附录绕过限制。
- 验收不仅检查页数，也检查每页必要性及跨页逻辑完整性。不能通过制造碎片化内容获得字号与留白的表面合格；合理共页的比较和因果关系应尽量同屏表达。

### 大纲的条件式确认

- 当组织方式、重点或演讲目标不明确，而且存在会显著改变成品的合理结构选择时，先向用户询问如何组织，再展开正式大纲和页面。可以带着 2–3 个简短备选方案，说明各自适合的目标并给出推荐。
- 例如产业主题可提供“按时间演进”“按产业链与厂商格局”“围绕关键判断与案例”三种结构；推荐应结合当前任务，不机械套用这三个选项。每个方案说明叙事顺序与侧重点，帮助用户选择。
- 主题、用途、受众和内容逻辑已经相对清楚，用户提供了大纲/参考结构，或明确授权自行组织时，直接推进，无需另设大纲审批。不能把“大纲确认”变成每次制作的必经停顿。
- 若封面、页数或关键用途也缺失，尽量合并成一轮简短询问。只问会影响结果的结构问题，已给出的信息不重复确认；不能仅因存在多个可行布局就认为大纲不清楚。
- 同一稿件后续修改沿用已明确的组织方向；用户改变目标或提出与现有结构明显不同的方向时，重新判断是否需要澄清。

- 适用于新建演示、换主题重新制作或重做整套 PPT，覆盖内置模板、自带模板及原创模式。已有文件的局部文字/样式修正、检查和只读问答不启动整套需求问卷。
- **封面需求必查**：用户明确要封面、不要封面或明确授权自行决定时直接执行；否则制作前主动询问是否需要独立封面。不能因模板没有封面就默认不加，也不能因模板有封面就默认加。
- **篇幅必查**：精确页数、“约 10 页”等约数或“5–10 页”等范围均视为已提供。没有时主动询问总页数或可接受范围，可以给出推荐范围供选择；用户未回答前不擅自定数开工。“你决定页数”属于明确授权，可按内容决定并告知。
- 总页数默认包含封面、目录和结尾页，在提问时简短标明。用户明确“正文 N 页，封面另计”时按该口径执行。用户给出范围时在范围内按内容定页，不需为最终精确页数再次确认。
- 主题、演讲用途、受众或必须使用的资料若缺失且会实质影响内容，合并到同一轮简短提问；上下文能够确定的信息直接沿用，不重复询问，不把字体等常规设计选择都变成必答题。
- 示例提问：“需要独立封面吗？希望总共多少页，或接受哪个页数范围（含封面）？”若页数已给，只问封面；若封面已明确，只问页数。此处获取需求，不是请求权限。等待必需答案时可读取已有资料和模板，但不开始依赖这些答案的正式大纲及页面制作。
- 承接同一份稿件时沿用已确认的封面和篇幅，用户修改要求时同步更新。新主题的新稿不机械继承上一稿的封面选择或页数，除非用户已明确设为持续默认偏好。
- 用户确认需要封面后，优先选本模板封面；没有时按正文视觉系统创建独立封面，保留主题、必要时间/对象等实质信息，遵守全部内容禁令和排版规则。封面也必须逐页可视化验收，最终 signoff 包含封面。

### 章节标识与导航确认

- 对有明确分节的中长稿，制作前确认章节如何标识：独立章节页、章节首张内容页加标识，或不额外标识。用户已指定该导航方式、明确要求沿用参考稿的章节导航、或授权自行决定时直接执行；短稿无分节需求不增加提问；篇幅短但明确分节且标识方式会影响布局时，仍确认所需方式。模板含章节页只是可用素材，不代表用户已经选择章节页。
- 选择首张内容页标识时，确认或按已授权设计选择标题前缀、标题上方章节名、侧边标记；明确仅每章首页还是全章持续显示。用户指定同一文本框、红色、附录灰色等照做；未指定颜色沿用协调的模板视觉体系，不默认一律红色。
- 独立章节页计入总页数；在原页数内分配，不能未经许可增加总页数。章节移动/增删后核对首页位置、正文/附录身份及标识连续性。
- 表达档位按[叙事参照](narrative-reference.md#表达档位与逐页职责)推断或询问；与本轮缺失的封面、篇幅等合并成简短问题，避免重复问卷。

## 内容禁令：不写制作说明和写作自我声明

### 自然语言与有依据的观点

叙事组织参照 [发布会原则与选择流程](narrative-reference.md)，先按用途选择方法，再组织核心判断与证据。该流程是参照，不是所有材料必须宣传优势的硬模板；客观比较、学术论证、复盘和教学按实际目的采用。下列语言规则用于减少泛化防御与制作自述，不要求隐瞒实质差异、风险、反证或方法条件。

- 分析型 PPT 要内容详尽、证据扎实，并提出作者的判断。组织方式为事实、变化机制、判断及实际含义；不要用一堆材料摘录代替分析，也不要用极简口号代替事实细节。
- 用户要求禁止免责声明及一切形式的防御性表达。删除“仅供参考”“不代表……”“不能据此……”“不等于……”“不提供……”“不做排名”“未经验证所以……”等惯用的退缩式尾句，不机械地给每页追加限制性副标题。主题本身确有风险或局限时，直接写具体问题、发生条件、影响和应对，不把它写成作者的免责话术。
- 同样拦截“先给正面判断，再补泛化限制”的隐性防御句，例如“优势是……；跨环境表现仍依赖……”“可靠性仍要在具体任务中建立”“购买额度只是起点”。不能仅删除“仍/只是”来保留同一语气；改为有来源支持的机制、具体行动或直接判断。例如前一句可改为“V-JEPA 2-AC 将视频表征用于动作搜索，每轮执行后根据新观察重新规划”。若依赖条件确是主题所需，写清具体输入、训练方式、适用对象和作用，不把泛化的限制句附在页尾结论栏。
- 语言验收与版面验收分别进行：生成前通读完整文稿，最终保存后重新提取全部可见文字、图表/表格文字、备注及母版，逐句审查，特别检查结论栏中的转折和补限制句。工作记录保存实际发现、原句与改写、复核结果；不能只填“语言pass”。关键词仅用于提出候选，不能代替语义判断，也不能机械禁止技术文本中的所有“依赖/条件”。保留真实的计划状态、日期、单位、估计或模拟属性，不以自然语气为名夸大结论。语言修改后重新渲染检查排版。
- 事实准确性仍是硬要求。以明确日期、单位、统计对象、来源归属和合适动词表达真实含义，例如“Anthropic 于 2 月披露的年化收入运行率”“微软观察研究估计采用者的合并 PR 增加约 24%”。保留必要的“计划”“估计”“模拟”等事实属性，不能为消除防御语气而把预测或模拟写成已实现结果。
- 判断应能回答“证据是什么、机制是什么、对谁有什么影响”。可直接写“竞争正在转向交付系统”“企业采购更应关注每个已验收任务的成本”，并在同页或前后页给出依据；不要用“显然”“必然”“全面颠覆”等无证据断言补强语气。
- 语言自然、具体、连贯，优先使用常用动词和完整句子。少用“赋能、重塑、生态闭环、范式跃迁”等空泛词，不机械重复三段式，不写制作过程或向读者解释自己避免了什么错误。标题直接点出主题或有证据的判断。
- 逐页检查可见文字与备注中的免责、防御和元叙述，发现后改成实质内容或删除；保留完整分析所需的事实，不靠清空内容过关。

- PPT 面向听众，直接讲主题、事实、论据、因果关系与结论。严禁描述“这份 PPT 如何制作、选材、组织、标注、验证或交付”，也不写为自己辩护的写作声明。此规则覆盖封面、副标题、正文、图注、表格、图表文字、母版与演讲者备注，不把违规内容移到备注规避。
- 明确禁止的实例包括：“发布记录、厂商披露与研究估计，分别注明口径和证据类型”“代表性国际厂商与公开研究”“不把部分年度资料写成全年结论”“本报告把事实与判断分开呈现”“本页用于展示复杂图表能力”“已渲染验收”“全部图表可编辑”“来源已放入备注”。这些可以出现在面向用户的聊天或工作目录的制作记录中，不进入交付 PPT。
- 不用机械的“本文/本页/本报告……”句式解释如何写这份材料；不把范围选择、资料检索过程、避免什么错误等说明塞进副标题。需要限定时间时直接写“2026 年 1—10 月”或“截至 2026-10-17”；需要限定主体时直接使用具体公司、地区或对象名称，不写泛化的“选取代表性资料”。
- 保留影响主题事实准确性的实际信息，例如“2026-02-12 披露”“美元/百万 token”“年化收入运行率”“单一组织的观察研究”“模拟数据”。它们解释的是事实或数据本身，不是作者的制作行为。不得因清理元叙述而把假设、模拟或部分年度数字伪装成已发生的全年事实。
- 来源标题、日期、链接、必要的测量定义及有实质内容的演讲提示可放入备注；制作步骤、排版测试和验收日志仅放工作目录。若用户明确以“如何制作 PPT”为演讲主题，则相应流程是主题内容，不属于本禁令。
- 交付前逐页阅读完整文字，并检查备注及母版，专门排查上述元叙述。发现一处就修改后重验。关键词匹配只能辅助发现，不能把“包含了主题流程图”误判为制作说明，也不能因自动检测未命中而放过语义相同的表述。

最终执行 `python scripts/audit_presentation_text.py <candidate.pptx> <work>/language-inventory.json`，阅读完整提取结果并逐句审查；图像内文字从真实渲染检查。语言审查绑定最终 PPTX 哈希，不能只处理关键词候选或转图片规避。退出状态按 [签核流程](signoff-workflow.md#错误传导与状态) 处理。

### 禁止自我限定与防御性说明

以下整类表述及同义改写均禁止进入交付 PPT：

| 禁止写法 | 处理方式 |
|---|---|
| 按实际发布日期排序；合作公告代表部署方向，不能替代已实现的业务效果 | 不解释排序规则。直接列出日期及事件；合作事件写“宣布合作/计划部署”，不要冒充已经实现的效果 |
| 基于公开产品能力归纳的典型链路；具体工具的权限与实现不同 | 直接以“代理任务执行链路”为标题，呈现具体环节；有必要区分的实现差异写进对应节点 |
| 同一基础模型可服务多个代理；以下比较产品路径，不做未经验证的能力排名 | 删除“以下比较/不做排名”等说明。主题事实可作为有证据的正文观点；比较表直接标明实际比较维度 |
| 不是截至 10 月的最新规模 | 改用具体数据名称和披露日期，例如“Claude Code 年化收入运行率（2026-02-12）” |
| 此页不把 API 单价、订阅价格和任务成本混在一起比较 | 各图直接标注真实指标及单位，例如“API 标价：美元/百万 token”，不说明自己避免了什么错误 |
| 不提供无来源的市场规模预测 | 删除整句。只呈现有依据的事实与结论；没有可靠依据就不添加预测 |

- 禁止在副标题、卡片、结论栏或备注中描述“我/本页/本报告采用什么方法、只做什么、不做什么、避免什么错误”。“仅用于说明”“不作排名”“不代表最新情况”等泛化的自我限定不能当作通用填充句。
- 副标题不是必填项。能补充实质内容就写具体观点、日期、对象或单位；否则删除并重新平衡版面，不用自我说明占位。
- 清理后仍须保持事实准确：用具体日期、统计对象、指标定义、合作状态、研究性质或“模拟数据”标签表达必要边界，不把不确定结论改成确定事实。区分“数据本身的定义”和“作者在讲自己怎么写”；前者按需保留，后者删除。
- 交付检查包含“自我限定/制作说明”一项，覆盖所有页和备注，按语义检查而非只搜关键词。若用户明确要求研究方法或局限性专题，可以呈现该专题的实质内容；不能据此保留讲述本 PPT 制作方式的句子。

## 文件属性与生成程序标记

缩略图与启动视图按 [交付外壳](delivery-shell.md) 统一处理：真实第一页、普通视图、适应窗口、PowerPoint后台运行。其余正常属性继续保留。

- 仅清除生成程序身份：Application、AppVersion，以及明确表示 generator、generated_by、creation_tool 等含义的自定义属性。禁止标注“使用某工具生成”。保留其他正常属性，包括标题、主题、关键词、描述、日期、修订号、公司等；不批量删除 docProps，不改动文件结构或内容。
- 作者按用户明确提供的信息，或幻灯片中真实的“作者/汇报人/编写者”署名填写。不能从报告讨论的公司、新闻人物、引用文献作者或工具名称推断作者。没有可靠依据时作者字段留空，不添加默认软件作者。
- 运行 `python scripts/strip_pptx_metadata.py <candidate.pptx>`；作者有依据时附加 `--author "姓名"`。再使用相同参数附加 `--check` 检查。无 --author 时清空作者字段；脚本不自行猜测署名。
- 构建器接入清理，并读取 edits.json 顶层可选的 author 字段；该值必须有用户信息或页面署名依据。其他作者工具也须在最后一次保存后清理，因为重存可能恢复生成程序属性。
- 清理在最终渲染、逐页检查和 signoff 之前执行。逐项验证保留属性与原值一致，清理不修改正文、图形、原生图表数据和来源备注。需要保留的标题/日期属性不是制作说明；PPT 可见内容和备注中的生成工具宣传仍禁止。

## 页尾与脚注：只保留页码

- 默认不允许页码以外的任何页尾/脚注，包括项目名、章节名、作者、日期、来源、版权、保密提示、测试标记、装饰口号及重复说明。检查并清理普通页面、布局和母版继承的内容，不能因为模板自带而保留。
- 页码全部统一为 `x/y`：x 为当前实际页序，y 为整稿总页数，例如 `1/14`、`14/14`。使用 ASCII 斜杠，不加前导零、空格或“第/页”等文字；独立封面也标 `1/y` 并计入总数。所有页面恰好一个页码，不缺失、不重复、不沿用模板原页序；重排、删页、增页后更新全稿分母和页序。页码采用普通顶层文本框，命名 `page-number:<用途>`，位置及样式全稿一致，仍遵守外边距与保护区。页码允许 10 pt，不把这个例外用于其他文字。
- 引用、来源、辅助备注放在演讲者备注中；影响读者理解的关键口径、单位、模拟数据标记保留在正常正文、图表标题或图例中，不做页底小字。不要为了规避规则把原页尾简单上移一点或改名为正文。
- 逐页渲染验收必须检查页底及母版元素；有非页码页尾或脚注即不通过。用户在具体任务中明确另行要求时按其要求执行，不需要每次重复提醒用户。

## 短文本必须完整、保持单行

- 短标题、卡片标题、表格行名及列名默认单行；不得把一个词的最后一两个字挤到下一行，或让短标签因换行撑高行高、越出表格。
- 先在不改变原意的前提下精简措辞；必须保留全文时，加宽文本框或表格列，并同步调整邻近元素、内边距和列宽，保持对齐与总宽度。不以删掉关键含义、截断或省略号换取单行。
- 不把“关闭自动换行”当作修复结果；关闭后仍须验证文字边界、遮挡和溢出。
- 长标题确需两行时按语义主动分行，行长协调；此例外不适用于短标签和表格行名。

## 字号和可读性

### 数字与单位保持同一行

- 数值与对应单位视为一个语义整体，默认不得跨行，包括正负号、范围、小数、科学计数及复合单位。例如 `12.52 kW`、`56 TWh`、`10 ms`、`3.5 GB/s` 应完整联排；不能让数值留在上一行、单位孤立到下一行。
- 优先调整措辞、框宽、列宽、局部位置或在数值前合理断句。需要时使用不换行空格（NBSP），并实际渲染确认宿主软件正确处理；不能只关自动换行造成溢出，也不能删单位或突破字号、页数和内容完整性要求。共用单位已清楚标在轴标题/表头时，无须给每个数值重复单位。
- 逐页内容遍与版式遍都检查真实换行，尤其正文末行、窄列、标签、公式及数字与单位分属多个文本框的组合。局部放大后回到整页，核对阅读顺序、间距和可读性。
- 只有确实无法用合理布局保留同一行时才允许例外：工作记录标明具体对象、完整数值单位、实际尝试和不能合理重排的原因，提供当前局部与整页图并由另一实际复核者确认仍清楚易读。不得仅写“空间紧张”自行免检；此说明只留验收记录，不写入幻灯片。

### 普通表格与正文的边界

- 普通数据表格通常至少 12 pt；调整列宽、行高、分组与布局后仍存在排版困难时，可以使用 10 pt，记录具体困难并检查整表及整页可读性。原生表格可命名为 `table:compact:<用途>`，预检按 10 pt 检查并加入人工复查项。
- 数据表格不适用 8 pt。8 pt 只允许确实无法合理拆解的复杂技术图中的必要局部文字、图形标签，并须完成 10 pt 障碍、保留必要性、布局调整、拆图不适用四项论证。
- 大段叙述即使放入表格单元格，仍属于正文；不能借表格或辅助注释名义获得 8 pt，也不能为了获得表格 10 pt 例外把普通正文批量搬进表格。应将长叙述重新组织为正常正文、分栏或关系图，保留必要内容。
- 10 pt 表格例外和 8 pt 局部图形例外按内容性质判断，不只依赖形状名称。禁止以多个文本框拼成伪表格、把全文转换为图片或修改对象名称来绕过标准。

### 代码字体与语法高亮

- 涉及代码块、终端命令、配置文件、日志、路径或行内代码时，可使用 **Consolas** 等等宽字体；根据环境可选 Cascadia Mono、JetBrains Mono、DejaVu Sans Mono 等。全稿同类代码使用一致字体，中文注释须检查缺字与字体替换。
- 按实际语言采用语法高亮：区分关键字、字符串、数字、函数/类型和注释，选择少量稳定颜色；浅色背景配深色文字，深色背景配明亮文字。注释也要可读，不能因降低对比度而看不清；颜色不能成为理解含义的唯一依据。
- 保持真实缩进、空格、括号与字符对齐。使用不同颜色的文本 runs 时仍保持相同等宽字体和字号，避免高亮改变字符间距。禁用会改变代码含义的智能引号或符号替换。
- 优先使用可编辑文本呈现代码，按完整语义选择片段。长行先调整代码区宽度，或按语言语法合理换行；不能裁切行尾、随意插入换行破坏命令，也不能为塞进页面而删除关键逻辑。需要省略非展示部分时清楚标识省略位置，不能冒充完整可执行代码。
- 代码正文遵守常规 12 pt 下限，通常采用 12–16 pt；代码注释属于代码内容，不能自动套用复杂图表辅助注释的 8 pt 例外。代码较多时调整布局、分段或按允许页数拆页。
- 代码容器遵守四边均匀留白、全页间距均衡及页码保护。渲染后检查高亮对比、缩进、换行、字符完整性和可读性，复杂片段可局部放大后再回到整页复查。

### 图内辅助注释的分级例外

#### 8 pt 的逐项论证与局部适用

- 使用 8 pt 前，Agent 必须针对每个例外对象写明以下四项，存入工作目录的验收记录：
  1. **10 pt 的具体障碍（必须来自实际渲染）**：先生成目标局部采用 10 pt 的真实候选文件，实际渲染并打开对应页面及局部，才可填写观察结果。记录页码、图表及对象标识、原文或精确文字范围、具体冲突对象与现象，例如“节点 A 的辅助标签与连接线 B 重叠”或“文字超出模块右边界 15 px”。必须保存该轮 PPTX 快照及 SHA-256、真实渲染整页图、局部图或可定位的裁剪范围；有定量描述时注明测量值、单位及渲染分辨率。不得根据字符估算、代码坐标或主观预测宣称 10 pt 已失败，不得虚构测量值。
  2. **内容保留的必要性**：这段文字承担的含义、删去或进一步简写会丢失什么关键信息，以及为什么需要就地呈现。
  3. **布局调整的结果**：尝试了哪些合理调整，例如扩大图区、移动标签、改变排列或层级、改用引线；为什么仍不能在 10 pt 下获得合理结果。尚未尝试的选项须给出具体不适用原因。
  4. **拆分图表的不适用原因**：拆分会如何破坏同屏比较、关系追踪或完整语义，或如何触及用户明确的篇幅约束；仅以“麻烦”“保持原样”作为理由不合格。
- 缺少上述任一项，不能把 8 pt 例外标为通过。`chart-note:dense:` 名称或自动预检通过均不是例外成立的证据，必须由逐项论证与实际可视化检查支持。
- **触发顺序不可倒置**：10 pt 候选实际渲染 → 打开整页与局部定位问题 → 在 10 pt 下尝试合理布局调整 → 再渲染复查 → 仍存在具体障碍才决定局部降为 8 pt。每次实际尝试保留相应版本证据；确实不适用的布局方案可说明原因，不要求制造无意义的失败尝试。允许预建空白记录模板，但不得提前填写“10 pt 失败”“8 pt 必要”或“验收通过”等结论；仅有提前写好的 `8pt_reasons.md` 不构成证据。
- 不得人为缩窄容器、增加无意义内容或故意采用劣质布局制造 10 pt 失败。前后对照必须保留同一必要内容与可比的实际设计条件；8 pt 版本与 10 pt 版本之间的布局/文字变化须记录。如果后续布局或内容变化已使 10 pt 可能合理容纳，重新尝试并渲染 10 pt，原例外不能自动沿用。
- **8 pt 只用于确有必要的局部辅助文字**。记录精确到文本框、标签或 run 范围；不能因一个标签困难而把整图的标题、坐标轴、图例、数据标签和其他注释统一降到 8 pt。其余文字保持各自适用的 12 pt 或 10 pt 档位。
- 同类元素统一样式的一般规则不能扩大 8 pt 的使用范围：必要局部可以作为明确例外，通过一致字体、颜色和对齐维持风格，而不是将其他文字一起缩小。
- 对最终 8 pt 局部单独放大检查，再回到正常展示尺寸检查整图和整页。仍不清晰时继续重构图表；不能用论证材料替代视觉效果。逐项通过后才能纳入最终 signoff，制作理由不进入 PPT 正文或备注。
- **与最终 Signoff 逐项绑定**：为每处 8 pt 例外分配 exception_id，工作记录关联四项论证、10 pt 各轮快照哈希及渲染证据、实际观察与修改、最终对象定位和最终 8 pt 局部/整页复查结果。Signoff 列出全部 exception_id 并绑定最终 PPTX 哈希；10 pt 试验哈希与最终哈希分开保存，不要求二者相同。最终扫描到的每处 8 pt 必须有对应记录，记录中已删除或移动的对象须更新；未使用 8 pt 则记录空列表，不要求制造试验。任一例外证据缺失、只有预写理由、未实际看图或最终对象不匹配，阻断签核。文件时间戳和报告存在只能辅助追溯，不能证明实际查看过图像。

- 字号规则用于保证可读性，不能成为放弃复杂图表、删减关键关系或把完整结构改成几句大字的理由。先完成必要结构，再调图表尺寸、层级、布局与标签；应用分级例外后仍须实际渲染，检查整页以及局部。图表完整性与可读性必须同时通过验收。

- **正常情况 12 pt；有困难 10 pt；有特别大困难 8 pt。** 尤其适用于信息密集、特别复杂的高级图表。其他画布按页面高度等比例换算。
- 范围限于图内非关键辅助信息：局部解释、辅助刻度、参考线说明、重复性细分标签等。正文、主标题、主要轴标题、单位、核心图例和理解结论必需的数据仍按常规下限执行。普通文字不得改名为“图表注释”来缩小。
- 先尝试增加图表空间、调整标签位置、避让连线、分组及保持含义的简写；仍困难时启用 10 pt；特别复杂且这些调整仍不足时才启用 8 pt。不是要求为了用较大字号删掉必要内容，也不把复杂图表一律缩成 8 pt。
- 同类辅助注释原则上统一字体、对比度及常规档位；8 pt 严格按必要局部例外处理，不要求其他注释跟着缩小。优先深色实字和清楚背景。8 pt 为最低档，不再向下缩小；仍不清晰时重新布局或拆分图表，同时遵守用户总页数要求。
- 工作目录的验收记录需逐项记载页码、图表/对象、采用字号、困难原因、已尝试的布局调整和可读性结果；不能把这类制作说明写入 PPT。先放大检查局部，再在正常展示尺寸下检查是否仍可辨认，两个尺度均通过后才可 signoff。
- 独立辅助文本框可用名称 `chart-note:compact:` 标记 10 pt 档、`chart-note:dense:` 标记 8 pt 档；普通 `chart-note:` 仍按 12 pt。预检对例外加入人工复查项，不自动代表批准；原生图表内的注释仍需逐项视觉核查。此例外不允许新增页尾或脚注。

- 标准 16:9（13.3333 × 7.5 英寸）演示页：正文、表格、图表坐标轴、图例及数据标签的可接受下限为 **12 pt**。正文通常用 14–18 pt，信息较密时允许统一使用 12–14 pt；不是要求所有文字一律降到下限。页标题建议 26–32 pt，短标题建议 16–22 pt，页码可使用 10 pt；图内辅助注释按上述分级例外执行；不允许其他页尾或脚注。其他画布尺寸按高度等比例调整。
- 上述是本地默认下限；模板继承的过小字号也要修复，不能因“模板原样”而跳过。检查主题继承字号、组合形状、表格单元格及图表内部文字，不能只看普通文本框的显式字号。
- 优先保留内容、调整栏宽和模块位置、统一使用合适字号（常规不低于 12 pt，表格与图内辅助文字按上述明确例外执行），再优化措辞。不得靠大幅删减内容、只留口号或把必要正文全部转入备注来规避排版问题。删除冗余可以，关键证据、例子、步骤、条件和结论不能丢。若确实需要拆页，须遵守用户页数要求。
- 同级标题和同类标签原则上统一字号，不随意单独缩小；已完成证据链的局部辅助标签例外按上述规则执行。必要的排版调整已获用户授权，无需为常规加宽、对齐或可读性修复重复询问。

## 对齐和间距

### 全页间距均衡

#### 模块平移、定量复验与签核证据

模块定义、12 pt 最小间隙、max(3 pt,20%) 容差、横纵两轴覆盖、整体平移、layout.json 与反规避要求统一见 [模块间距量化](layout-integrity.md#模块间距量化)。必须执行，定量检查与可视化检查缺一不可。版式数值失败按签核流程修复或完成局部＋整页独立视觉兜底，保留原报告与阈值。

- 大标题到正文的距离默认略紧凑，避免在主标题、副标题、分隔线之间累计出大段空白。常规调整可先收紧约 0.10–0.15 英寸，再看最终渲染；这是调节起点，不是所有页强制相同的绝对数值。正文充实的页面优先腾出主体空间；特别空的页面可按整体构图保留较大间隔，不能把内容都挤在上方。

- 标题区应紧凑并与主体密度相称。主标题、副标题、横线、空档和再重复一次的大字判断不能层层占位，把表格、图表和结论压到页面底部。发现此类结构时先压缩标题层级并提升主体位置，再分配模块间距与底部留白。
- 副标题、小标题均按需设置，不要求每页都有。仅保留承担具体分组、补充事实或表达关键判断的标题；与主标题重复、为套版式而加、没有实质信息的标题直接删除。必要日期可以并入标题或相关指标名称，避免为一个短日期占用整条高大的副标题区。
- 标题区压缩后必须重新布局主体，不能留下原副标题的空白占位，也不能把所有内容一股脑上移造成新的下半页空洞。按最终可见内容复查整页上下和左右的空间分配。

- **高优先级发布硬门槛：全部页面的横向和纵向间距都必须通过验收。** 不抽样、不以多数页合格替代全稿合格，也不以“自动检测通过”替代视觉判断。任一页面存在明显不均衡即不得 signoff 或发布。
- 每页单独记录 `horizontal_balance` 与 `vertical_balance`。横向检查左右列宽、列间距、图标与文字距离、图表与解释间距、容器左右留白及左右视觉重量；纵向检查标题/副标题/主体/结论之间距离、行与模块节奏、容器上下留白、页码保护区。两项均为 pass 且无未解决问题，才可将该页标为通过。
- 在正常展示尺寸下逐一查看整页，同时检查最紧和最松的间隙。明显失衡需重新分配整页空间，再次渲染和独立复查；整稿最终签核要求每一页两项均衡检查完整。

- 对每一页统一规划标题、副标题、图标、主图/表格、解释与结论区，先扣除页面外边距和页码保护区，再分配高度；不要先固定上方布局，最后把结论硬塞到剩余位置。
- 所有间隔应与内容层级相称：同一层级、同一类型采用一致间距；组内标题与正文紧凑，独立模块之间适度拉开。可用 4/8/12/16 pt 等间距档位保持节奏，不能把“匀称”机械理解为不同层级的所有间距绝对相等。
- 逐页同时比较上、中、下区域及左右列的实际可见空隙。上方存在大块闲置而底部文字贴住表格、结论覆盖末行、图例挤压正文、内容侵入页码区，都判定失败。
- 表格/图表的边框、正文可见范围、图例和注释都计入占用区域；表格外结论与最后一行必须有清晰间隔，不能只依据文本框坐标或空白包围框判断。
- 修复时重新分配整页空间：上移主体、调整图标区和标题区间隔、优化行高/模块高度，并在 12 pt 下限内统一调整同级字号。保留必要内容，禁止通过删减关键信息、覆盖末行或挤压页码解决。
- 每次修复都重新渲染并独立查看受影响页，记录间距、重叠和全页均衡的复查结果；最终仍须全页逐一查看并 signoff。自动预检无报错不代表间距均衡。

### 有色文本容器：四边均匀留白

- 适用于所有有色文本框、信息卡片、标题条、提示框及文字所在的有色面板。无论是单一自带文字的形状，还是背景色块叠加多个独立文本框，均按一个容器检查。
- 先为每类容器确定统一内边距，四边使用同一基准值；标准页面的信息卡片可从 0.20–0.30 英寸开始，按字号和容器大小调整。同类容器保持一致，不只设置左右边距而忘记上下。
- 以实际可见文字、图标等内容的联合包围框为依据，测量它到容器内侧四边的距离。段落末行自然长短不要求拉齐；但不能用大而空的文本框尺寸伪装实际留白均匀。标题、数字和正文作为一组布置，最上方与最下方的可见内容也须保留等量空间。
- 目标是四边视觉等距，只允许字体轮廓带来的微小光学调整；明显的上松下紧、左紧右松、末行贴底均不通过。无论四边是否相等，任何文字、图标、笔画越界或被裁切都不通过。
- 修复顺序：调整容器与内容组的位置/宽高，统一内边距，重排标题、段落和组间距，再在已授权字号范围内统一调整。必要时改用更适合完整内容的布局；不得删掉必要信息、添加无意义文字填空、拉伸字形或缩到字号下限以下。
- 设置四个 margin 属性相同只是起点；固定高度容器中的空余空间仍可能导致不均。必须看最终渲染，单独检查每个有色容器的四边可见空隙，并在修改后重新渲染。

### 页码保护区与层级

- 页码所在区域专用，不与正文、表格、卡片、装饰条、图片、图表或它们的描边/阴影共享。以页码文本框为中心向四周额外预留至少 3 pt 的隔离空间，内容不得侵入。
- 页码必须完整处于页面安全区内，文本框高度和宽度足以显示所有数字及分隔符；全稿位置一致。页码最后添加或显式置于最上层，不能让后添加的白色矩形、表格底色等覆盖它。
- 顶层显示不能替代隔离：禁止把页码叠在表格/卡片上，即使数字暂时可见。发现冲突时移动或重新布局主体内容，同时保持既定外边距，不能把页码挤到页面外。
- 自动预检检查页码保护区与其他对象边界的相交，真实全幅背景除外。母版对象、阴影、裁切与实际图层效果仍须从最终渲染逐页确认；只检查坐标、未查看渲染不能宣称页码无遮挡。

- 同组卡片、图表、表格及文本框共用明确的左边线、顶线或中心线；同类元素等宽、等高或按内容采用一致规则，间距一致。
- 修改宽度或字号后重新检查文本基线、框内边距和相邻元素位置。表格行名左对齐、数值列右对齐或按小数位对齐，标题与对应内容对齐。
- 保持页面边距和跨页同类标题位置一致。禁止文字碰边、覆盖边框、压住图表或伸出页面；不要让修复一处造成另一处错位。
- 保留用户刻意指定的不对称设计，不机械地把所有内容居中。

### 内容充实与视觉均衡

- 编辑前列出每页需保留的核心信息，完成后逐项核对。把完整分析缩成几句大字不能算排版修复；不为追求极简而删掉原有逻辑与证据。内容准确、完整与版面均衡共同构成交付门槛。
- 按实际渲染中的文字、图表和图标判断视觉重量，不能用一个横跨全页但右半为空的文本框伪装占满空间。右侧或左侧出现无意的大块闲置、内容挤在另一侧的页面不通过，即使无溢出、字号和边距都合格。
- 发现明显单侧闲置时，优先尝试等宽对照、三栏、主图加解释、步骤横排、证据与结论并列，重分配模块宽度与位置；必要时让相关图表更完整、展开已有推导。合理留白仍保留，不能靠虚构内容、重复文本或无意义装饰填空。
- 不强制左右完全对称，但不对称必须有明确的主次关系与视线引导。逐页记录“视觉均衡通过/需修复”，不得把自动预检无报错等同于美观或均衡。

### 复杂图标、图表与图解能力

#### 高级科学图表工具

- 学术、数学、实验、统计与仿真内容可按需要调用已经可用的 Python、MATLAB、LaTeX、R、Julia、Octave、Graphviz 等工具，详见 [科学绘图工具与环境选择](scientific-visualization.md)。Windows 同时探测本机与已有 WSL；不存在或不可用的工具/依赖跳过，不自动安装或激活环境。
- 工具选择服务于科学表达。简单图保持原生可编辑，高级科研图可使用适合的矢量/高分辨率输出，保留工作目录中的数据与源代码。以最终插入尺寸及真实 PPT 渲染验收，局部清晰度和全页均衡共同通过才可发布。

#### 全稿综合使用多种图表形式

- 用户明确要求综合使用多种形式的图表。大纲阶段为每页写明信息任务与图表形式，在数量/关系/过程/时间/结构等任务之间选用不同表达，不把换色、换图标或重复柱图当作图表多样性。
- 分析型多页演示，在数据支持时结合条形/柱形、折线、环形、散点等原生定量图，以及时间线、比较矩阵、流程、架构和关系图。正文解释图表的意义，图表承担比较、趋势、占比、联系或决策流程的表达。
- 不设脱离内容的类型配额；禁止为凑环形图捏造市场份额、为凑折线图虚构时间序列，或对没有自然顺序的类别画“趋势”。同类指标需要直接比较时可保留同一种图型。
- 交付前检查全稿图表组合与版式变化，并逐图核对单位、数据、图例、轴线、关联和可编辑对象。用户明确指定图型或强调多样性时，应在交付中实际体现，不能只写入规则而不执行。

#### 图标搭配与页面变化

- 用户偏好在适合的内容中综合使用多种图标，避免全稿只有重复文本框、表格和同一种装饰。设计时主动识别可用图标表达的对象，例如组织、模型、代码库、云环境、工具、审批、成本与风险；为不同语义选用不同图标，而不是反复使用同一个符号。
- 全稿保持一致的图标语言：优先同一图标库或同一设计体系，统一线性/面性风格、线宽、视觉尺寸、颜色及与文字的间距。多样性来自语义与组合，不来自随意混用 emoji、照片式图标、线稿及不同风格素材。
- 可使用细节较多的图标、图标组或带图标的复杂流程/架构图，只要在实际呈现尺寸下清晰可辨。优先可编辑矢量或高质量 SVG；品牌标识使用准确的原始素材并保持比例。
- 图标用于识别对象、区分类别、提示方向或强调关键点，不能替代重要文字、数字、单位与逻辑关系；不凭空添加内容来凑图标。不设每页最低图标数量，数据密集页可以少用，避免图标喧宾夺主。
- 全稿按信息结构交替使用带图标的对照、时间线、流程/架构、数据图表等版式；不为了变化破坏同类元素的一致性。图标组也须遵守容器四边均匀留白、页面边距及页码保护区。
- 渲染验收同时检查图标含义、清晰度、风格一致性、文字对齐和整体均衡；发现装饰重复、视觉噪声或遮挡时调整。复杂图标可以保留，但不能以过小尺寸或不明含义换取所谓丰富。

- 允许多图表分析页、组合图、散点/气泡图、带条件分支及反馈回路的流程图、架构图和有信息价值的复杂图标。取消每页最多 4 个元素或信息点的硬限制；复杂度由内容逻辑决定。
- 优先使用原生可编辑图表、文本、节点及连接线。复杂图标可采用 SVG 或高质量矢量素材；不要求为了“简洁”删掉必要的图例、关系、分支或节点。
- 分类图使用 CategoryChartData；XY 图使用 XyChartData；气泡图使用 BubbleChartData。组合图应复用经过验证的原生组合图模板或使用可验证的实现，明确两轴单位及对应系列。接口不支持某图型时切换正确的原生 API，不用静态截图冒充可编辑图。
- 对复杂图至少检查数据点/系列一致性、轴单位、图例映射、标签遮挡、节点包含关系、连线方向、分支条件及回路归宿。复杂图的主要标签遵守 12 pt 下限，辅助注释按 12/10/8 pt 分级规则执行，同时遵守页面外边距，不能靠缩成小图绕过。
- 修改复杂图表相关能力后，至少生成一页多图表分析页及一页带分支/回路的流程或架构图，保留编辑对象，实际渲染、目视检查，并重新读取 PPTX 验证数据与对象结构。测试用模拟数据明确标注；不能只验证脚本运行成功。

能力修复的复测样例及结果保存在任务工作目录，覆盖实际修改的图型、数据、标签、连线及视觉均衡；不把单个样例通过推及未经测试的图型。

### 页面外边距下限

- 固化为可复用下限：标准 16:9、13.3333 × 7.5 英寸页面的**左、右、底部外边距均至少 0.35 英寸（约 8.9 毫米、25.2 pt）**，建议留到约 0.44 英寸。其他画布按高度等比例换算：最低为页面高度的 4.67%。不要把水平百分比直接套到底部，造成实际留白变小。
- 内容卡片、表格、图表、文字和它们的可见边框都必须落在安全区域内，不能边框贴底或贴侧边。测量最外侧可见边界，包含描边和明显阴影；文本框内部留白不能替代页面外边距。全幅背景色、背景照片及用户明确要求出血的装饰除外，内容面板不属此例外。
- 排版前先确定安全区域；内容放不下时重排栏宽与模块、调整内部间距，必要时在 12 pt 下限内统一调整同级字号。不能遮挡内容、把面板向页外延伸或大幅删减内容。
- 逐页渲染验收时同时核查左右与底部留白。默认低于上述下限即不通过；模板原有贴边布局也要修复。

## 必须渲染，逐页验收

执行 [签核范围与证据流程](signoff-workflow.md)，这是全量/增量范围、真实渲染、错误传导、双遍逐页视觉检查和发布状态的唯一规范。默认全量所有页；只有已全量签核后用户指出局部问题的修订可依该文件执行严格增量复验。未全量通过的稿件不得自设局部例外。

数学图与定量图逐项核对数据、坐标范围、刻度间隔、数字格式和单位，防止小数刻度被整数格式舍入成错误标签；标题、轴标签、数据表、图例和自定义标签均属验收范围，不能互相遮挡。

## 辅助层级、表格、裁图与色调

- 标题/关键结论/关键数字承担强调，辅助来源、日期及次要条件通常用常规字重与协调的灰色；必要的定义和图表读法维持主体可读性。检查是否大面积粗体或彩色让主次失焦，不机械按所有辅助文字变小/变灰处理。
- 同类说明列采用一致的段落对齐、垂直锚点、行距与内边距，表头与对应正文一起核对。数值列可按右边或小数位对齐，也可按比较用途居中；文字列与数值列职责不同可采用不同规则，不能一律强制全表同对齐。合并单元格、多行首行、空值和继承样式均纳入检查。
- 图例、数据标签、坐标轴和图区作为实际占用区域核对；图例不能压住柱顶数字，长中文名称替换后重查图内空间。优先移动图例、调整图区/标签位置，保留数据和必要说明。自动几何不足时局部与整页复核继续执行。
- 科学图片插入前检查有效主体和白边/透明边界，按内容裁剪与放大。比较组采用可比较的裁剪范围、比例、坐标和视角，保留必要背景、尺度、图例与完整主体；禁止逐图自动紧裁而改变相对位置/大小。裁剪后检查真实对象是否被截断，不能把浅色对象、轨迹或坐标误当白边删掉。
- 对“表/图—说明—流程/结论”连续结构，说明是明确的待检查模块；逐段比较可见上下间隔及邻接关系。灰色文字、原生表格、组合和图内元素不能因样式或对象类型漏掉。具体阈值与移动方法沿用既有间距规则，不另设冲突阈值。
- **有色块内优先白字或黑字/近黑字。** 根据底色明暗和实际可读性选择：较深、饱和的色块通常适合白字；亮黄色等明亮底色通常适合黑字。不能把“大部分色块白字更好”变成所有底色强制白字。
- **同类、同级模块尽量统一字色方案。** 同一组卡片、流程节点或按钮中的对应标题与正文优先使用一致的中性字色，模块内部主要通过字号、字重和间距建立层级。不能仅因背景颜色不同就让同级文字随意切换蓝、黑、白；需要统一白字时，协调调整相关底色以保持清晰度。确有用途的代码高亮、数据系列、状态警示、重点强调或用户指定方案按其语义保留，区别应明确且全稿一致。局部检查文字与底色，再回整页及跨页比较同类模块；统一性与可读性一起验收。
- **黄／橙强调色优先干净、明亮。** 未指定复古、大地色等风格时，尽量避开偏棕、发闷的土黄色，可改用清爽的黄色或明亮橙色。需要承托白字时结合色相、明度和饱和度选择，避免只压暗黄色而变成浑浊棕黄；局部检查白字可读性，再回整页看与其他色块的协调。用户指定的品牌色、自然主题或复古风格按其实际目标使用。
- 彩色字用于明确的语义区分或强调时可以保留，但必须同时核对文字/底色的协调、饱和度、对比度和整页层级。例如黄色块配高饱和蓝字应作为审美复核候选，不能仅因颜色可辨便放行；警示、品牌和用户指定的配色按实际目的判断。
- 色调检查同时看色块底色本身的色相组合、明暗、饱和度，以及主色、强调色、中性色比例和全稿一致性；避免底色彼此不协调、过于昏暗或浑浊、大片高饱和色互相冲突；深色主题可保留深底，但需通过明暗层次和清晰主体形成有意的风格。少量强调色承担明确职责，避免每个卡片都争夺注意力。对比度数值仅辅助发现风险，审美和实际阅读效果须看正常整页及必要局部；实测失败走修复或已有独立视觉复核，禁止改阈值自授免检。
