# 签核范围与证据流程

本文件是所有模式的唯一签核范围规范；其他文件的“最终全页检查”“修改后重验”均按本文件确定范围。内容、字号、布局、连接和证据标准不因范围变化而降低。

## 范围判定

- **默认全量签核。** 新建、重做、尚未全量通过的稿件，以及不满足下列增量条件的修订，最终候选必须实际渲染全部页面，逐页完成内容遍与版式遍，再签核。中途可局部迭代；未完成首次全量签核不能利用“改动小”“用户只说一处”或局部导出获得例外。
- **唯一增量场景：已经全量签核后，用户指出局部问题，执行相应调整。** 先核对最新文件；问题已解决且文件未变时保留原有效签核，不无意义重跑。确需修改时按同等签核标准核验全部受影响页（不仅截图所在页），保留有效全量基线及新增修订证据。用户明确要求不全量重跑时亦须满足本前提，不能据此跳过未验收页面。
- **增量影响范围必须有证据。** 记录用户原始局部指正、基线/修改后 PPTX 与 Skill 版本哈希、变更对象、受影响页清单和判定依据。比较其余页 XML、关系及所引用资源；共享母版、布局、主题、字体、资源、页数或页码变化可能扩展影响范围，必须逐项追踪。范围无法可靠界定、基线无效、旧版已知漏检没有完成追查，或规则升级导致旧证据不再适用时，回到全量。
- **增量不是改写旧报告。** 保留旧文件、旧报告及原哈希；受影响页使用当前实际渲染、同等自动审计和双遍视觉记录。最终标明“此前全量签核＋本次受影响页复验”，同时绑定基线与当前文件，准确记录本次复验页范围。校验器不能验证该证据链时，保持未签核并修复流程或执行全量，不绕过校验。

## 执行顺序

技术字段与新旧协议边界统一见 [机器证据接口](evidence-schema.md)。范围校验、人工复查、字号例外与coverage职责分开；任何单个工具返回0都不代表全部检查已经完成。

1. **固定候选与规则。** 最后保存后清理生成程序元数据并 `--check`，按 [冻结规则](layout-integrity.md#冻结skill后再迭代和签核) 检查 Skill 锁；输入、模板和素材各记哈希。布局前确定完整内容、安全区与可读字号，真实数字需有来源或可复算依据，模拟/演算保留标记。
2. **真实渲染。** 先按 [交付外壳](delivery-shell.md) 从稳定候选生成真实第一页缩略图并保存普通视图，再进行本步骤的只读全页渲染；默认后台不弹窗。 Windows 有 PowerPoint 时优先 `scripts/render_powerpoint_audit.ps1`；否则用可用真实渲染器并补足等效审计证据。使用锁定的唯一稳定快照，记录打开前及完成后哈希；源文件或快照变化则整轮作废。不能用模板预览、代码截图、坐标重画或旧图替代成品。渲染不可用时尝试替代，仍不可用则不得签核。
3. **规则检查。** 执行元数据、渲染预检、layout gaps、独立 coverage、连线、全文语言与最终证据校验，逐项解决所有报告、人工检查项和视觉新增发现。最终 review 绑定原始 layout/gap 报告；独立发现的原生图表—图注—结论关系另核对真实像素边界，即使框距通过也不省略。详见 [间距证据接口](evidence-schema.md#原始间距报告与可见图表边界)。仅字符容量预警不证明溢出，但任何真实溢出、过小字、错位或不当换行必须修复。检查代码、表格、图内标签、母版与备注，不只普通文本框。
4. **内容遍。** 按页码顺序独立打开规定范围的每页真实 PNG，以正常展示尺寸阅读完整内容，检查可读性、图表语义/数值/轴单位/数字格式、语言、跨页逻辑和信息完整性。禁止只看 contact sheet、缩略图、抽样或自动报告；contact sheet 仅补充跨页一致性。
5. **版式遍。** 同一未变候选逐页检查 [完整布局范围](layout-integrity.md#版式遍逐页检查范围)，可倒序减少惯性。检查断字、孤行、字体替换、同行/同列/跨栏、光学边缘、图表与图片内部、四边留白、外边距、横纵均衡、全部连线与页码保护。强制局部场景按对应规范执行，所有发现逐项对照；两遍可复用同一份未变真实渲染，不为凑轮次重复导出。
6. **局部与迭代。** 复杂、密集或自动无法可靠测量的区域，裁取当前真实渲染放大检查文字、笔画、箭头、图例、节点和冲突；随后回到正常整页，检查清晰度、间距、整体协调及页码。不能用原 SVG、旧局部图代替。每次内容、字号、位置、尺寸或样式改变后，重渲染受影响页，核对原问题并找新增问题；最终重新完成本文件规定范围的全部检查，不设放行轮数上限，也不制造无意义修改。
7. **签核。** 每页记录页码、真实图路径及哈希、实际查看、最紧/最松留白、横纵均衡、问题/动作/复验结果；缺失、未知、待处理或疑点均未通过。运行 `verify_coverage_review.py` 并核对当前全部证据；`evidence_complete_pending_visual_signoff` 不是自动发布许可。完成语义与实际视觉验收后，签核记录执行者、时间、最终文件哈希、总页数、范围/有效基线、逐页证据、所有 8 pt exception_id（无则空列表）及零未解决项。8 pt 必须有真实 10 pt 试验链，见 [字号规则](local-delivery-quality.md#8-pt-的逐项论证与局部适用)。禁止提前批量填通过或仅凭记录存在自证看过图。
8. **交付。** 签核后才复制/导出/上传成品或提供最终链接，复制后核对 PPTX 哈希一致。任何后续修改撤销对应签核并重新按本文件判断全量/增量范围。用户明确索要草稿可提供标明未验收的草稿；不能称成品。验收记录只放工作目录或聊天，禁止放 PPT 正文或备注。Signoff 是执行者真实验收记录，不额外要求用户审批。

## 错误传导与状态

- Windows 调用 Python 工具优先 `python -X utf8 ...`；Python 父进程捕获子进程文本时同时明确 `encoding="utf-8"`（或读取原始 bytes 后按实际编码解码）。父进程用 UTF-8 打开日志文件并不能改变子进程编码。构建器额外保证旧编码日志中的不可表示字符只转义显示，不改 PPTX 原文；仍须检查真实退出码，不能用忽略异常、`errors="ignore"` 或删除内容解决编码问题。

- 任何非零退出先保留原结果并分类，PowerShell 外部程序后显式检查 `$LASTEXITCODE`，不能让后续成功覆盖失败。执行异常、未知状态、缺页/报告、旧哈希或无法解析输入先修复，停止依赖这些失效证据的步骤；已完整渲染但版式预检失败，仍须继续规则与视觉交叉复核，按下文兜底闭环后继续，不把非零一律当作任务终止。
- `rendered_pending_visual_review`、`geometry_pass_pending_visual_review`、`manual_review` 和 `evidence_complete_pending_visual_signoff` 均不是发布许可。coverage exit 2 表示发现待核查项，应修复或以可验证证据确认误报，再完成证据校验；exit 3 表示工具/输入失败，须先修复。语言 exit 2 为候选、3 为提取失败；0 仅无预设关键词，仍需读完整提取文本和图像文字。
- 渲染顺序执行，目录不得并发复用；PowerPoint 使用目录锁及失败报告，LibreOffice 使用全新目录。失败目录残留图片不能拼成完成证据；不能在导出后才首次计算输入哈希。
- 更新检查失败必须非零，允许明确记录失败后使用已安装有效版本，但不称最新；更新应用失败查看 result.json 并恢复，`rollback_failed` 先恢复安装再使用，检查与应用必须同一更新源。
- Git 检查／暂存有超时且禁用交互式凭证等待。超时后保留原安装，修复网络或使用 `apply_update.py prepare --candidate <已审查的本地候选> --stage <新目录>` 继续。保护注册表和更新状态原子写入；结果提交失败或 Ctrl+C 触发回滚。若磁盘故障使失败报告也无法写入，以终端明确的恢复状态及实际文件核对，修复存储后补足记录。强制结束进程或断电可能无法执行清理：发现 `applying_not_complete` 或不完整暂存时，先对照 plan.json、rollback 备份与实际文件恢复一致状态，再更新或使用；不直接把半更新文件当作新基线。恢复时保留无法确认来源的后续修改，不能盲目覆盖用户新内容。
- 发现漏检立即撤销相关版本签核、保留失败历史，并追查全稿同类问题。工具修复不能删对象、压掉告警或降低真实缺陷标准；正反回归及当前版本实际核验完成后再签核。

## 版式规则未通过时的视觉兜底

**规则与视觉交叉检查是必做流程；规则返回失败不等于最终视觉失败。** 对间距、对齐、容器、文字边界、图表及连接等版式判断，保留原告警、原测量及原阈值。如果当前局部和正常整页都实际检查通过，并经另一位真实复核者确认，可以关闭对应拦截，继续其余检查和签核；不要求每个版式数字机械地返回通过，也不要求符合某个预设图型才有兜底资格。框边界、字形分割、对象关系推断乃至稳定测量的数值差，均需结合实际视觉关系判断。

兜底不能由作者自授：

1. 先完整运行原检查，保存完整原报告、失败项、当前 PPTX 与渲染图哈希。不得删告警、改数值/阈值、合并模块或新增透明代理来制造通过。
2. 裁取当前真实 PNG 的原像素局部，覆盖全部相关对象与足够结构上下文；逐处核查字形、图形、间距、线端、遮挡和可读性。再返回同一张正常尺寸整页，确认横纵均衡、邻接关系、页码及阅读顺序。记录规则为何未通过、局部看到什么、整页为何合格，而非只有“视觉通过”。
3. 由另一位实际复核者查看相同局部和整页，独立确认具体对象关系和全部原失败项。可使用独立 subagent 或用户实际复核；作者不得伪造身份、消息来源、图像查看或预填通过。若是对齐关系误推断，复核必须区分同一指标/同行组件与真正独立模块；“职责不同”本身不是证据。
4. 按 [机器证据接口](evidence-schema.md#版式规则失败与不确定项的视觉闭环) 绑定原始失败、全页对象、当前局部/整页及独立复核。闭环结果记为 `visually_resolved_pending_signoff`，不覆盖原报告的失败状态；继续全部未完成的检查、全量双遍和最终签核。实际可见缺陷、复核分歧或未解决疑点继续修正、渲染和复查。

完整性和内容要求另行执行：缺失/过期证据、漏页/漏对象/漏检查、执行异常、虚构数据、页数或页码内容错误、低于适用字号且未完成例外证据等，不能靠“看起来正常”关闭。先修输入、程序或内容，保全有效证据，再继续。对照同一原始版本判断真实问题，不以新画的示意图替代渲染。

**拦截是处理中间状态，不是停工结论。** 误报与规则无法定论的问题走上述视觉闭环；实际问题迭代修复；工具故障排查并修复，或采用可验证的等效工具/证据。没有现成适配器时应实现最小适配并验证正反例，不能反复以“当前不支持”把任务退回用户。普通使用任务只在工作副本修工具，未经明确授权不修改长期 Skill；已获持久化授权时合并修复、测试并冻结后恢复验收。只有确实缺少完成任务必需的外部输入或所有可行渲染路径不可用时，明确具体障碍与所需条件，保留未完成状态，不能伪造交付。

原测量不确定项的专用证据协议继续兼容，但不是通用兜底的资格白名单。真实置底背景、纯色色样图片、复杂轮廓和无色框混排等都照常检查；不为迁就检测器添加噪声、边框或多余组件。

## 渲染器使用与检查边界

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '<skill-root>/scripts/render_powerpoint_audit.ps1' -InputPptx '<candidate.pptx>' -OutputDir '<work>/fresh-render' -ExportPdf
$renderExit = $LASTEXITCODE
# 非零须读取 audit.json 分类：执行/证据失败先修复；完整渲染的版式失败进入视觉闭环，不能忽略后直接签核。
```

脚本生成 PNG、可选 PDF 与 audit.json，检查有效字号、文字边界、左右/底部安全区、短标签换行、标点独行、原生数据标签重叠和页码。取不到原生标签/组合内部几何、混合或未知字号等进入人工检查；轴刻度、曲线、图例、位图文字、阴影、语义换行与实际遮挡均纳入局部和整页视觉检查，逐项记录结果。

自建对象可命名 title:/subtitle:/short:/page-number: 辅助识别；仅真正出血背景可命名 background:。命名、未标记对象或底部 10% 自动识别不是合格依据；页尾与母版残留仍须视觉检查。规则所需全页对象/文字清单与版本哈希必须保全。
