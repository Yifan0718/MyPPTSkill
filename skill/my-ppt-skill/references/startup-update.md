# 启动更新检查：轻量提示，制作照常继续

本会话首次启用MyPPTSkill时执行一次，可与读取用户资料等准备工作并行：

```text
python -B -X utf8 scripts/startup_update.py
```

## 根据结果行动

- `should_prompt: true`：简短告知检测到的MyPPTSkill或上游模板版本，询问“现在更新”或“本次继续使用当前版本”。两条更新线同时有更新时合并询问一次。等待答复期间继续读取资料、梳理内容等独立工作；用户未回复时沿用本机版本，不等待更新决定才能制作。
- `should_prompt: false`：直接继续当前任务。没有更新、网络不可达、超时、限流、远端元数据异常或启动检查工具自身失败，都不要求用户处理、不反复重试、不询问是否排查网络。
- 只有用户明确选择更新才进入更新流程。用户选择跳过或未选择时，不下载、不安装、不覆盖规则。本次任务不重复询问同一更新。
- 用户主动取消执行按取消处理；这与普通网络检查失败分别处理。

启动检查总时间预算最多5秒，每条来源最多2秒，读取元数据上限1MiB。DNS阻塞、慢响应和慢数据流均由父进程墙钟时限终止；启动不调用Git克隆，不请求登录，也不安装网络工具。缺网络时沿用有效本机Skill完成原任务。

## 两条版本线

- `MYPPT_VERSION`：本机MyPPTSkill发布版本，检查本项目GitHub最新稳定Release。
- `VERSION`与`updates.json`：上游GordenPPTSkill模板基线，保留原有更新机制。
- `startup-update.json`保存启动元数据地址，并将上游元数据地址绑定到实际`updates.json.update_source`；两者不匹配时跳过这条启动检查，避免提示一个来源却应用另一个来源。
- 预发布、草稿、旧版本和相同版本不会触发更新提示。MyPPTSkill发布版本与上游模板版本各自比较，不能互相比大小。

## 检查状态与制作状态分开

启动结果始终保留每条检查的真实状态和`error_code`。`check_unavailable`表示本次未取得可验证更新信息，不能写成“已是最新”。`workflow_action: continue_local`表示继续制作，与网络检查成功无关。

启动适配器正常返回建议时退出0；遇到用户取消退出130。严格诊断工具`check_update.py`继续保留原有非零失败码，可在用户明确要求排查更新时使用。构建、渲染、更新应用和最终签核继续按各自真实错误状态处理；启动可选检查不成为它们的依赖条件。

可选`--report <工作目录中新文件>`保存诊断；未指定时只输出JSON，不写入安装目录。报告路径冲突或写入失败保留诊断，继续原制作任务。

## 用户确认更新后

上游模板更新沿用`apply_update.py prepare`的保护入口。MyPPTSkill发布升级先读取确认版本的安装包、校验清单及更新说明，在工作副本核对候选内容，再使用保护暂存／审查流程。两种更新都保留用户已固化的额外要求，明确冲突先向用户说明并确认；完成后验证安装与规则，重新冻结当前任务版本。

用户答复到来时若已有构建或渲染正在运行，先到达该阶段的稳定边界，再执行更新；更新后重新冻结规则，按影响范围复核。签核过程中保持规则与候选稳定。

下载或暂存失败、且原安装完整时，沿用本机版本继续任务。应用过程按已有事务回滚与恢复规则处理，保证原有效安装和已完成的文稿得到保留。
