# 与上游的差异：额外要求与解决的问题

MyPPTSkill fork 自 [GordenSun/GordenPPTSkill](https://github.com/GordenSun/GordenPPTSkill)。此文以本地保留的上游 1.0.20 为基线，按功能解释当前定制，不记录开发时间线。精确执行规则以 [SKILL.md](../SKILL.md) 及引用规范为准；许可归属见[许可说明](LICENSE_SCOPE.md)。

## 继承与总体改变

保留上游 21 套模板、模板索引与槽位信息、内置／用户模板／原创三种模式、原生文字与图表编辑，以及原来源和许可。

上游入口强调只替换文字、保持原位置和字号；原创模式限制单页元素数量，示例将最终渲染写为可选，并在首次使用时直接应用更新。定制版改为：保留风格但修复缺陷，复杂度服从内容，真实逐页验收必做，更新先检查／暂存／审查并保护定制，再应用。

## 需求、内容与叙事

| 额外要求 | 当前行为／解决的问题 |
|---|---|
| 封面与篇幅确认 | 未说明时主动询问；封面默认计入总页数，已知信息不重复问；模板没有封面时按原视觉系统制作 |
| 大纲条件式询问 | 组织方式有实质歧义时给备选方案，目标清楚时直接推进 |
| 模板真实预览 | 指定模板直接用；通常展示三套实际第一页，候选不足时如实展示，有更多时可换一批，不展示模板广告拼图 |
| 内容翔实、有观点 | 保留证据、机制、必要步骤、例子和结论；不只堆摘录，也不靠口号稀释信息 |
| 禁止制作说明 | 不写“本页如何选材／验证／交付”等自述；正文、图注、表格、母版和备注都检查 |
| 禁止泛化防御 | 删除“不做排名”“仅供参考”“不提供无来源预测”等写作声明；实质条件融入主题内容 |
| 事实与自然表达 | 保留日期、来源、估计、模拟、计划等事实属性，不能以消除免责声明为由夸大结论 |
| 副标题按需 | 不每页硬加解释文字、重复小标题；删除后重新分配空间 |
| 发布会原则作参照 | 按任务选择问题→缺口→思路→结果，证据有职责、优势主动说清、结论强化记忆；教学和研究不强行宣传 |
| 客观比较 | 选与目标相关的维度，真实解释权衡；不换分母、隐藏关键反证或编造合理化理由 |
| 不机械拆页 | 不靠删关键内容、缩字、空洞页面或碎片化拆页规避密度；指定上限不越过，隐藏页计入总数 |

见[默认交付标准](../references/local-delivery-quality.md)和[叙事选择流程](../references/narrative-reference.md)。

## 字体、字号与代码

| 额外要求 | 当前行为／解决的问题 |
|---|---|
| 常规字号下限 | 标准 16:9 页面常规文字至少 12 pt；正文通常 14–18 pt、页标题建议 26–32 pt、短标题建议 16–22 pt，页码可 10 pt |
| 表格 10 pt 例外 | 优化列宽、行高、组织后仍困难才使用，复查整表与整页；大段正文不能装进表格取得例外 |
| 图内辅助文字分级 | 正常 12 pt，困难 10 pt，极复杂技术图必要局部才 8 pt；不因字号限制放弃必要复杂图，也不把整图统一缩小 |
| 8 pt 真实试验 | 先真实生成、渲染并查看 10 pt，定位具体冲突，尝试合理布局后再决定；禁止提前填失败理由 |
| 8 pt 论证范围 | 解释具体障碍、必须保留的内容、布局为何未解决及不能合理拆图的原因；普通表格、正文和代码不适用 |
| 8 pt 签核绑定 | 每项 exception_id 关联试验快照／哈希／观察、最终对象和局部＋整页检查；条件变化后重新考虑 10 pt |
| 代码等宽与高亮 | 可用 Consolas 等宽字体及合理语法高亮，代码正文常规至少 12 pt；注释不自动获得 8 pt 资格 |
| 数字与单位 | 尽量不换行，检查图内、表格及正文的联排；不能把对应单位无意落到下一行 |
| 短文本完整 | 不截断或用省略号硬凑，检查孤字、标点独行、字体替换及混合字号 |

见[字号和可读性](../references/local-delivery-quality.md#字号和可读性)。字号例外须逐项满足适用条件与证据要求。

## 间距、对齐和可见边缘

| 额外要求 | 当前行为／解决的问题 |
|---|---|
| 全页横纵均衡 | 全部页面检查水平及垂直，比较最紧／最松间隙，不以多数页或自动通过代替全稿验收 |
| 标题区紧凑 | 收紧标题到正文距离，避免副标题、横线及重复判断层层占位，挤压主体和结论 |
| 页面安全区 | 标准页面左、右、底至少 0.35 英寸，建议约 0.44 英寸；其他画布同比缩放，包含描边和阴影 |
| 容器四边留白 | 看真实文字／图形联合范围，不只看 margin；自然末行不要求拉齐，明显上松下紧或越界不通过 |
| 模块平移与复验 | 可整组上下／左右平移、改尺寸、等距分布；同步移动背景、节点、箭头和标签，再测量及渲染 |
| 间隙量化 | 同级独立模块默认至少 12 pt，目标容差 max(3 pt,20%)；按真实层级比较，不为过审重分组或放宽阈值 |
| 坐标＋实际字形 | 所有位置还要检查可见笔画起点、中轴、右边缘；肉眼错位不能因落在坐标容差内放行 |
| 混合字号／字体 | 大数字与小标题、标题与副标题、不同字体并列等强制局部视觉检查 |
| 图表及侧栏整组 | 核对真实绘图区、标签、图例和说明组，不能漏掉侧栏第三段或将图片白边当可见边界 |
| 中间说明行 | “推进条件”等同时核对与上下模块的间隙，不把行本身框距当整体均衡 |
| 图内居中数字 | 圆环等图中的中心文字按实际可见宿主居中，不按外框或作者自述中心放行 |
| 跨页一致性 | 同类标题、页码、配色、图标语言和锚点一致，同时保留用户明确的不对称设计 |
| 页码保护 | 每页唯一 x/y，含封面，至少 3 pt 隔离；置顶不能替代安全距离，不允许遮挡 |

执行[布局验收](../references/layout-integrity.md)和[对齐与间距](../references/local-delivery-quality.md#对齐和间距)。按真实语义层级组织匀称间距，同级模块统一节奏。

## 复杂图表、图标与科学工具

- 取消单页最多四个元素的限制；按内容组合多图表、流程、架构、分支和回路，不靠单调文本框填满全稿。
- 多种图表承担不同论证职责；图标丰富来自语义，保持统一体系、线宽与视觉尺寸，不设每页最低数量。
- 分类、XY、气泡图使用正确数据接口；检查系列、轴单位、刻度格式、标签与原始数据，不把静态图冒充原生可编辑图。
- 按需使用已安装 Python／Matplotlib、MATLAB、LaTeX、R 等，Windows 同时检测已有 WSL；不统一强制某一种工具，不假称运行。
- 复杂图内部局部放大，随后回看整页；自动测量不了的部分进入真实视觉复核。
- 关系线逐根逐端检查目标、方向、接触位置；短末段、回折、分叉、交叉、多段拼接重点核验，防止箭头悬空。
- 图标笔画、时间轴和关系箭头区分语义与几何验证，不能只改名称来获得豁免。

见[科学绘图](../references/scientific-visualization.md)、[图表编辑](../references/chart-editing.md)、[连接完整性](../references/connector-integrity.md)。

## 签核与反规避

1. 所有页面初始未验证，真实逐页完成内容遍与版式遍，contact sheet 仅作辅助。
2. 每次修改后复验；必要时反复迭代，没有为了尽快发布而放过可见问题的轮数限制。
3. 声明之外独立扫描实际对象、文字、组合、图像、图表、表格、母版与布局，内部结构不得漏检。
4. 禁止把独立模块合成一个 block、添加透明代理、扩大空白文本框、改 background/title 名称或调阈值来清除告警。成组不豁免内部检查。
5. 规则失败保留原始结果。当前局部＋整页合格且独立复核者确认，可关闭对应版式拦截；作者不得自授免检、伪造复核身份或预填通过。
6. 缺页、旧哈希、执行错误、虚构数据、缺字号证据等必须实际修复，不能转成视觉误报豁免。
7. 最终渲染使用稳定快照；打开前和完成后检查源／快照哈希，最终图片和所有报告绑定同一候选。
8. 默认全量签核；仅已全量通过后用户指出局部问题的修订可严格增量。保留原签核，不伪改旧哈希；共享资源变化扩大复验范围。
9. 工具故障要排查、恢复或采用可验证替代，不把拦截当停工结论，不拿失败目录残留图冒充完成。

见[签核流程](../references/signoff-workflow.md)和[机器证据接口](../references/evidence-schema.md)。校验器检查记录完整性与一致性，执行者完成实际看图和视觉判断。

## 已解决的工具与交付问题

| 问题 | 当前处理机制 |
|---|---|
| 更新入口吞掉内部失败 | apply_update 传递真实返回码；失败／回滚失败非零，不被后续成功覆盖 |
| 上游覆盖额外规则 | 自动发现本地差异、新规则、删除项；快照、审查、冲突确认、哈希保护和回滚 |
| 容量计算忽略错误对象 | 缺失形状／非文本对象显式失败，不输出貌似有效的旧容量 |
| 渲染完成后才算输入哈希 | 渲染前后检查稳定快照与源文件；全局串行锁协调 PowerPoint |
| 失败或未知状态放行 | 区分执行失败、待人工复核和最终签核；未知状态、缺项、过期证据拒绝 |
| 审计误关联不同职责的文字 | 基于实际区域／容器／组件判断，必要时独立局部＋整页复核；“职责不同”一句话不是证据 |
| 图内重叠和标点孤行漏查 | 渲染预检、覆盖扫描、局部视觉共同检查；取不到几何则明确进入人工项 |
| 广告缩略图遗留 | 包级缩略图和模板选择预览均取实际第一页，清除旧宣传缓存 |
| PNG 包级缩略图打不开 | 包级使用兼容 JPEG，正文和外部预览仍可 PNG；最终实际首图重编码比较 |
| 冷启动与再次打开字距不同 | 首图准备与正式渲染采用同样的后台只读预热导出，再正式重开；预热临时图不作证据 |
| 打开模式不正确 | 文件内保存普通视图与窗格，保留合理缩放信息，不擅改用户应用偏好 |
| 窗口弹出打断工作 | 默认后台无窗口；只关闭自身文档，异常路径释放自身资源和锁 |
| 过度清理元数据 | 只清生成程序身份；作者有依据才填写，其他正常属性保留 |
| 元数据清理覆盖并发编辑 | 使用唯一临时文件，提交前复核源哈希；检测到外部变更时保留外部文件并要求基于稳定候选重试 |
| 更新结果记录失败或中断 | 最终结果写入包含在回滚事务内；Ctrl+C 触发尽力回滚，失败状态写不下时仍输出实际恢复结果，不报成功 |
| 保护注册表写入中断 | 临时文件写入、同步后原子替换，提交前失败保留原有效注册表 |
| Git 等待或凭证交互卡住 | 有限超时、非交互环境，超时受控非零返回，可重试或使用审查过的本地候选 |
| 外壳写入半完成 | 源哈希保护、原子提交与条件回滚，不覆盖并发外部修改 |
| 开发残留混入安装包 | 移出测试、夹具、历史日志、宣传素材与缓存；上游新增开发文件也过滤，机器更新元数据保留 |

以上机制贯穿构建、审计、修复和交付；每份新稿都通过实际渲染与视觉验收完成验证。

## 更新、授权与发布边界

额外要求覆盖内容、字号、布局、视觉核验、科研工具、代码、页码、作者、缩略图、视图及后台运行等。保护依据是文件差异与注册表，不靠固定关键词白名单；未来新增文件也能发现，已注册删除项不会复活。

明显冲突必须显式确认；暂存后要求变化使旧更新计划失效。新上游模板清理广告缓存，预览重新生成。明确保护的用户自定义文件优先于通用开发文件过滤。

普通单稿反馈不自动成为长期规则；仅明确授权才修改安装版。发布包保留 LICENSE、NOTICE、来源、上游版本基线和保护注册表。测试与历史证据另存，不是运行依赖，也不能让新稿免检。

|---|---|

| 模板 | 保留视觉内容，替换缩略图／preview、规范视图、记录首图信息；不是给全部模板原始页颁发版式合格认证 |
| 发布内容 | 开发资料外置，保留操作必需的脚本、规范、更新保护与分层许可 |
