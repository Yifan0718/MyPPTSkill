# 用户反馈与修订闭环

在当前任务工作目录维护一份精简记录，已有记录可复用；不要为同一信息创建多份日志。普通反馈只约束本任务，长期Skill修改仍需用户明确授权。

## 记录当前决定

- 保存当前有效的受众、表达档位、章节标识、篇幅、术语和用户特殊约束；用户纠正后更新有效决定，并注明被替代的决定，避免撤回意见重新进入成品。
- 大纲为每页确定稳定的任务内标识、论证职责、关键证据与前置概念。页码随重排变化，稳定标识用来关联讲稿、引用、章节和术语定义，不写入Slides。
- 每次反馈记录具体问题、相关对象/页面、同类扩查范围、修复位置和当前复验结果。检查记录绑定候选及真实渲染，完成状态以实际成品修改和复验结果为准。

## 用户指正一处，追查同类

- 用户用截图举例说明某类问题，或新增适用于全稿的规则时，默认扩查整份文档；只有用户明确限于某页/某对象时才按其局部范围执行。不能把“给了一个例子”解释成“只改这一个”。
- 改动前逐页列出同类对象及其语义职责，改动后逐项记录实际处理与当前图像。辅助备注检查应包括页底说明、图后读图提示、符号/API释义、卡片内补充、跨页指引和参考资料；同时列明作为正文保留的关键口径、主要结论与必要解释。不得因为没用“注释”命名而漏掉。
- 同类角色优先共用样式或配置，避免每页零散设置导致漏改。当前实例中Beamer辅助备注可共用宏、PowerPoint可共用字体/颜色样式；样式名本身不证明实际角色或验收通过。
- 新增全稿规则、共享样式或实际同类扩查涉及全稿时，本轮重新做全量签核。先前按旧规则或遗漏范围的通过记录不能作为当前放行依据。完成声明必须能对应逐页对象清单、实际变更与保留理由、当前局部/整页复核以及未解问题清零；只修截图示例不构成闭环。

- 按问题类型扩查：一个未定义指标→同类指标/缩写；一张说明表对齐不一→同类表格；图例压数值→同类图表；说明上下间距失衡→同结构页面。
- 判断问题为何未被先前检查发现：缺定义、范围遗漏、工具测不准、关系推断错误、修复未进入成品或复核观察不充分。记录可验证事实，不凭聊天推断具体工具故障。
- 用户指出过的类别在最终复核中显式回查。关闭时写明实际改了哪里、同类对象查了哪些，以及新渲染的结果；不得仅填“全稿通过”。修复后的页面还要检查相邻对象和新增换行。

## 变更影响

- 术语、字号、颜色、数据、框宽或图例文字变化，重查关联组件、同类页面及可见边界。
- 重排/增删页后同步页码、章节首页标识、首次定义、前后指代、备注链接、讲稿转场、计时及输出索引；检查正文与附录的身份。
- 仅文字等局部修订符合既有严格增量条件时，复验全部受影响页面并保留全量基线；重排、共享资源或影响范围不明时按签核规则回到全量。不能用稳定页面标识替代当前文件哈希或放宽签核范围。
- 同一未变候选可复用真实渲染做不同视角检查；无需为了记录轮数重复导出。排版、内容检查有明确分工，检查者之间共享当前候选身份与已修复问题，独立理解检查的初次阅读仍保持无作者答案。
- 进度更新说明本轮发现、实际完成和下一项具体检查，避免反复只说“最后签核中”。工具拦截继续按恢复/视觉兜底路径处理，既不跳检，也不因误报停工。
