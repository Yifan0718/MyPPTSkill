# 全页覆盖与反规避验收

本文件补充 local-delivery-quality.md，所有生成、修复与签核任务必须执行。对象不越界、字体合规、横纵轴各有一个比较组，不代表全页布局通过。

## 高敏感检查与反复迭代

- **默认所有页面有问题，初始状态一律为 suspected_unverified。** 这表示必须找证据排除问题，不要求虚构缺陷。新页、模板页、复制页、封面、未改动页都不能预填通过；缺记录、无法确认、工具未覆盖均保留未解决状态。自动 issues=0 只说明该工具未检出，不能把初始状态直接改为签核通过。
- **规则与视觉必须双向交叉。** 规则发现逐项回到真实渲染定位；视觉发现补进问题台账，并追查为何规则没有覆盖、是否影响其他页。规则通过但视觉有疑点，或视觉看似正常但规则问题未核实，均不得放行。最终每页对应当前 coverage finding ID 的完整处理清单；不能只看未报警页，也不能只看报警区域。

- **宁可多报待核查问题，不放过尚未确认的异常。** 怀疑错位、遮挡、过紧、失衡或检查能力不足时，状态为未解决，先阻断签核。误报通过实际图像、关系和测量证据确认后才能关闭；不能以告警太多、已经迭代很多次、赶时间为由放宽阈值或跳检。“错杀”指保守拦截待核查，不是删掉必要内容、扭曲数据或强迫所有数据点等距。
- 不设“最多修改两轮/三轮”之类放行上限。每次修复后实际渲染受影响页，先核对原问题，再找新引入的问题；未解决则继续调整。环境故障、渲染不可用或证据不足时保留未完成状态，不能把重试耗尽写成通过；确有外部阻碍时如实报告。
- 最终候选完成**两遍不同视角的逐页检查**，绑定同一 PPTX 与最终渲染哈希：内容遍检查可读性、图表含义与语言；版式遍暂时不依赖叙事，专查对齐、间距、容器、连线与页码，可倒序检查以减少惯性。可重复使用同一份未变化的真实渲染，不要求无意义地重复导出。任一遍发现问题并修改后，旧记录失效，按 [签核范围判定](signoff-workflow.md#范围判定) 完成最终两遍；两遍是最低检查视角，不是固定迭代次数或自动放行条件。
- 工作目录维护问题台账：发现版本/页码/对象、实际现象、测量、修复动作、重渲染版本、复查结果。状态仅从“待核查”进入“已修复待复验”再到“复验通过”，或有证据的“确认误报”；不能直接从发现问题跳到无依据的通过。不允许 ignored、wontfix、稍后处理等未解决状态进入成品签核。

## 从布局设计预防错位

- 先确定栅格、公共左右边界、行中心/基线、栏宽、模块间距、容器内边距和页码区，再放内容。同类组件使用同一套坐标/样式参数和构建函数，不为每个卡片随意手填坐标；同组元素移动和尺寸调整由公共锚点推导。
- 各关系预先选择对齐准则：编号/图标与单行标题用可见中心；多行标签与正文明确首行或整体中心；同列指标统一左边缘或共同中轴；表格数值按列右对齐或小数点对齐、单位统一；公式/行内代码核对真实基线。一个关系不能在失败后换准则规避，用户明确的新设计要求除外。
- 字体、字重、段前段后、行距、文本框四边内距及垂直锚点统一管理。混合中英文字体、数学符号、等宽代码、不同位数数字分别看实际渲染，不能假设框坐标相同就对齐。模板原有自动缩字、继承样式、阴影/反射和字体替代先检查。
- 内容、字号、框宽或框高发生变化，会影响换行、文字中心和邻接间距：同步重算关联标签、背景、图标、引线和结论条，不只挪动一个对象。不得通过扩大空白框、添加不可见框或缩小内容骗过边界检测。

## 版式遍逐页检查范围

| 关系 | 实际检查重点 |
|---|---|
| 标题、副标题与主体 | 是否有必要；实际可见上下边界；标题区是否挤压正文；上下留白是否失衡 |
| 同行编号、图标、标签、标题 | 字形中心/首行关系；混合字号；图标光学中心；不以顶端相同替代居中 |
| 同列数字、单位、说明 | 全组共同锚点；数字长度变化；单位与数字的基线；不漏掉第三块文字 |
| 多行正文、表格与矩阵 | 行名与对应行；列宽、单元格留白；小数/单位；跨行、断字、孤行；表头与正文分开核对 |
| 颜色容器与卡片 | 内容整体与背景一起检查；上下及左右内边距；内外两套间距；同类卡片统一。自然段末行参差不等于内边距失衡，不为齐右边缘拉伸文字 |
| 左右图文、多个图表 | 两栏整组可见顶底/中心；同级图尺寸、绘图区及图例位置；避免一栏下坠或一侧大块闲置 |
| 图表内部 | 轴标题、刻度、图例、数值标签、点线与网格的冲突；小多图同类轴对齐、共用量纲时尺度一致；不为版式修改真实数据位置 |
| 流程、架构与回路 | 节点/连线/箭头端点；直线、折线和曲线全路径；不穿文字；标签不压线；分支方向明确 |
| 图片、矢量和分组 | 内部留白、裁切、透明边界及组内子对象；外框合格不能替代内部局部检查 |
| 页边与页码 | 左右底部安全区、页码独立保护区；x/y 顺序/总数；母版残留、遮挡、层级 |

正常显示尺寸检查阅读效果，放大检查疑似问题和复杂局部，再回到整页判断光学平衡。局部放大可帮助发现问题，不能用于证明正常展示尺寸下的小字也可读。重复组件只要发现一处问题，扩查全稿同类组件。

## 不允许用声明取得免检

### 先确认检查关系，再判断是否错位

- 横向投影相交不等于同一列。扫描先读取真实段落左/中/右对齐方式，并按对应锚点建立邻接；不得把左对齐正文、居中节点、全宽总结经传递关系合成一个“巨型同列”。12 pt 的锚点邻域仅用于提出关系候选，不改变实际对齐的 2 pt/像素验收阈值；范围外对象仍进入关系待复核，不自动通过。
- 空形状名、空单元格名等COM空值必须规范化并保留记录，不得崩溃或丢弃对象。表格、图片、组合内部继续逐项实际检查；未知段落继承方式保留待核查。
- `text_region_relation_requires_review` 表示“先查是不是同列”，不是“已经确认错位”。需按当前真实PPTX对象几何填写下面的关系契约，并提供当前局部图/整页复查。工具重读对象验证，不能只写“层级不同”“误报”或改名来通过。

| relation_contract.kind | 必填证据与自动约束 |
|---|---|
| different_alignment_roles | shape_ids完全覆盖该finding；PPT段落设置确实不同；还须common_visual_anchor及整组可靠PNG字形验证，局部与整页证据齐全；仅角色不同不能放行 |
| spanning_region | 实际宽块至少为被覆盖块宽度的1.5倍且横向包覆；例如跨栏总结。每栏内部对齐仍查 |
| hierarchy_indent | levels按shape_id给出0–5层，indent_pt为6–48pt（按画布缩放）；原生左对齐，实测缩进与层级步长差不超过1.5pt；图上层级关系真实清楚 |
| separate_visible_containers | containers映射每个成员到实际不同、可见且包含它的容器；不可用透明大框或白底无边框伪造 |

关系契约格式为 `relation_contract: {kind, shape_ids, visible_relation_explanation, ...}`，包含对应行的附加字段；levels/containers用字符串shape_id作键。必须精确覆盖finding成员并通过当前文件的几何校验，缺失、虚构对象、错误缩进及不支持的类型均失败。关系确认后，容器内部、同层兄弟、文字/连线和光学边缘仍不能免检。该流程允许证明真实层级/分区，不允许豁免真实缺陷。

白色不等于不可见：真实不透明白色矩形/圆角面板在灰色或有色背景上，可由当前渲染中四边内外的对比证明边界；仍须验证原生填充、真实包含、分离关系和当前局部/整页。透明代理、白对白、只有不相关白块证据不能通过。不得为了迁就颜色判定而给本已清楚的容器强加描边；轮廓无法可靠测量时按视觉兜底规范保留待核查并补证据。

- 图表与表格上下排布时，额外检查原生Chart的实际PlotArea、轴标签与表格可见边界；两者外框等宽不构成可见右边缘对齐。渲染器记录 chart_geometry_records，发现差异时用当前局部图决定并修复实际失衡，不能仅引用Shape.Width。
- 同列紧邻的图表与表格默认共用数据区可见右边界。先检查原生图绘图区右界（plot_bounds_pt[2]）及实际PNG，再调整下方表格宽度/列宽保持内容完整；不能因为原生图内置边距而让表格超出。`chart_table_visible_edge_requires_review` 的COM实测差大于2pt进入待复核并暂缓签核，但COM不是字形/图形像素真值。若实际可见边缘已一致而COM有舍入/布局偏差，可用下述真实扫描线证据证明；局部可见偏差即使更小也继续光学复核。不得用“不同模块”“外框相等”或数据坐标标签豁免。用户明确要求不同构图时重新定义任务布局，不自行推断豁免。
- 绘图区/表格像素证明字段为 `plot_table_edge_evidence: {slide_width_pt, pixels_per_pt, chart_rows_px:[...], table_rows_px:[...]}`。两对象各选至少3条不同、稳定且确实穿过可见右边界的扫描线；校验器从当前PNG自行计算边界，不信任填入的边缘数字。扫描线须在真实对象内、靠近实际边界、结果稳定，且两组边缘差小于像素阈值；背景复杂或没有稳定边界时继续局部视觉核查和修复，不能伪造扫描线。实际右边缘仍错位的原F/H样例必须拒绝，真实像素对齐但COM偏移的样例才可通过此项。
- 跨页标题按角色、字号/字重及真实段落对齐方式分组，核对实际笔画锚点；封面独立构图不强制使用正文框坐标。框坐标偏移仅提出光学复查，不能硬阻断用于字形补偿的微调。同类正文标题仍检查全组；禁止只改字号、字重或命名逃离跨页一致性检查。

### 图内居中文字与可见宿主

环图孔洞、仪表中心、节点、图标或其他图形中的居中文字，必须绑定其**实际可见宿主/孔洞**，比较当前渲染中可见轮廓中心与整组字形中心；图表外框、COM PlotArea、文本框中点或原生“居中”设置只能辅助定位，不能替代真实像素。数值、单位和多行说明属于同一中心标签时先按完整语义组核对整体中心，再查组内对齐/行距，不把每一行各自挤到孔洞中心。保留必要的视觉层级，不按笔画墨量重心机械居中。

所有此类文字强制检查当前局部放大图，再返回正常整页复核。测量显示偏差时先核对当前局部与整页；实际可见错位则平移完整文字组或调整真实布局，重渲染并复验；视觉合格而规则未通过时走通用独立复核。不能换成图表外框中心、改名或自行声明来放行。自动轮廓、文字分割或可选测量依赖不可用时，保留明确人工项，走局部＋全局且有独立复核的视觉兜底，不把“测不准”当通过或永久中断。图片/矢量/组合内部也适用本要求，机器尚不能可靠解析的场景仍必须实际看图。

### 工具错误与真实版面问题分开修复

**版式规则失败不是永久死锁。** 数值测量与同行/同列关系推断都保留为检查证据，不单凭失败数值宣布视觉不合格。按 [局部＋整页独立视觉兜底](signoff-workflow.md#版式规则未通过时的视觉兜底) 实际复核通过后，可以关闭对应版式拦截；真实可见缺陷仍修复，漏对象或失效证据先补全。阈值、原失败与全部检查不删减，接口见 [视觉闭环](evidence-schema.md#版式规则失败与不确定项的视觉闭环)。

1. 工具崩溃先保留输入、退出码和原错误，修复空值/解析等执行故障；运行同一失败样例证明已消除，并确认对象与发现没有被删掉。
2. 关系误识别修复候选判定或增加可验证的结构契约，不降低真实缺陷阈值。回归同时包含“应通过的合理结构”和“必须拦截的真实错位/像素偏差”。
3. 旧覆盖报告和旧签核记录不迁移为通过。工具修复后，用当前安装版重新渲染/扫描、逐项核对，完成内容遍和版式遍，才进入证据校验。不得因已知一条误报而把其他尚未检查的条目批量关闭。
4. 普通任务无明确持久化授权时，最小补丁仅放任务副本并保留精确diff；用户明确要求修复Skill时才合并到安装版、补充回归与流程，并继续完成当前稿件验收。修改脚本不是放行，自动检查通过也不证明实际看过图。

### 冻结Skill后再迭代和签核

- 修复Skill期间先暂停使用它的执行者，不边改规则边让其填写最终验收。完成正反回归、真实失败样例验证和文档一致性检查后，恢复执行者；执行者重新读取当前规则并使用同一冻结版本完成后续迭代。
- 更新检查和获授权的Skill修复完成后，运行 `python scripts/skill_state.py snapshot <work>/skill-lock.json`，记录规则、脚本及配置文件哈希；旧锁文件不覆盖。模板、论文和使用的图像资源另外记其实际文件哈希。
- 开始最终检查及签核前运行 `python scripts/skill_state.py check <work>/skill-lock.json`。返回非零或任何文件变化，停止依赖步骤，创建新版本锁并重新完成受影响的检查；不能仅更新锁文件而沿用旧通过结论。按 [签核范围判定](signoff-workflow.md#范围判定) 检验旧证据是否仍有效；不满足严格增量条件时，新版本必须全量渲染并逐页两遍检查。
- `coverage-review.json` 顶层必须包含 `skill_lock: {path: "锁文件绝对路径", sha256: "锁文件SHA256"}`。verify会在开始和结束核对安装Skill状态，并重算coverage、核对实际图像哈希；规则或脚本中途变化均阻断签核。这个锁证明使用的版本一致，不替代实际看图。

- 禁止合并独立模块规避间隙审计。同一 block 的多个 shape_ids 必须有真实空间包含关系（共享一个实际可见的容器），或确属同一组件的标题与正文。没有共同容器的独立视觉模块必须分开。页面上方图表与底部结论不能合成一个 block。
- 组件标题与正文虽可在设计中成组，审计仍需检查它们的内部间隙；无包含关系时，使用单对象 block 分别测量，不能仅写 component_reason 取得自动通过。独立卡片组成的一整行可用于整体移动，但不能作为免查内部水平间距的单一审计 block；纵向可逐列建立单对象比较路径。
- 禁止添加不可见/透明大框、扩大文本框、改名 background/title、塞进组合形状、合并比较组、调大容差、移动到 manual_axes 等方式消除告警。共同容器必须实际存在且语义成立；容器内部也必须验收。
- manual_review / manual_axes 表示待检查，不是免检；不得只写“人工通过”“设计需要”“不同层级”。必须记录具体对象、真实渲染图位置、测量或观察、修复与复验。无法获得内部几何时做实际局部图检查，不得写成自动通过。

## 模块间距量化

禁止通过合并独立模块规避间隙审计：多 shape_ids 必须有真实共同容器或属于同一组件的标题/正文；无共同容器的分离模块拆为单对象 block 检查，组件内部也不得免检。布局分组、background 命名、manual_axes 与人工检查标记均不能授予免检。最终签核另须包含独立 coverage 报告、每页最紧/最松间隙与真实文字对齐证据。

- 每页声明实际内容模块及同级间隙比较组：例如“上栏流程—下栏应用—结论条”的纵向间隙，以及同一行卡片之间的横向间隙。以模块中可见容器、文本、图形的联合边界计算；嵌套元素属于同一模块，不把容器与自身文字当作两个相邻模块。
- 为同一节奏组指定目标间隙。标准页面独立模块默认至少 12 pt；每个间隙与目标的差异不超过 `max(3 pt,目标的20%)`。按画布高度同比缩放。不同语义层级可以使用不同目标，但必须事先明确分组，不能发现失衡后任意拆组或放宽容差来过关。
- 典型失败：上栏到下栏31 pt，而下栏到结论10 pt。修复可把下栏整体上移、结论条下移或调整相关高度，使两段间隙回到同一目标。允许**整组上下平移、左右平移、调整模块宽高、等距分布同级模块**；优先使用已有空白，保持内容、字号、连线关系及页码保护区。
- 平移时内容与背景一起移动；节点移动后同步更新连接线端点、箭头和标签，不能只挪色块或正文。调整宽高后检查重新换行和实际文字边界。
- 保存 `layout.json`，运行 `python scripts/audit_layout_gaps.py <candidate.pptx> <layout.json> <gap-report.json>`。每页必须覆盖横向和纵向；确无同级多模块可比较的轴，填写具体 `manual_axes` 原因并做视觉复核，不能直接当作自动通过。
- 比较项格式：`{name, axis, target_gap_pt, blocks:[{name,shape_ids:[...]}]}`；shape_ids 为顶层对象 ID，可用多个对象组成一个模块。默认最小间隙12 pt，局部紧凑分组需要更小值时说明真实设计理由并单独验证。分组不得漏掉结论条或最紧的间隙。
- 每次局部调整后重新计算 gap-report，并重新渲染、独立查看整页。记录调整前/后各间隙值、目标、误差和可视化结论。**定量检查与可视化检查缺一不可**；数值不合格须修复或完成通用独立视觉兜底，不能省略测量。只写“均衡通过”而没有比较组、实测值及实际复核不满足验收。
- 几何工具只测对象边界。图形内部留白、阴影、文字实际换行、原生图表内部细节仍须按实际渲染检查；不能将几何通过直接当作视觉签核。

## 全页清单与独立扫描

1. 在布局前定义真实模块及其横向/纵向邻接关系，覆盖标题到主体、每层内容、模块内标题/正文、主体到结论、结论到页码保护区。记录所有相邻独立模块的间距；指出全页最紧和最松的间隙，而非只挑容易通过的比较组。
2. 执行 audit_layout_gaps.py 检查声明的比较组；该脚本拒绝无包含关系的多对象 block。真实包含关系也只进入人工核对，不自动证明是同一组件。
3. 用最新 render_powerpoint_audit.ps1 实际渲染，再运行独立扫描：

```powershell
python '<skill-root>/scripts/audit_layout_coverage.py' '<candidate.pptx>' '<render>/audit.json' '<work>/coverage.json'
$coverageExit = $LASTEXITCODE
if ($coverageExit -eq 3) { throw '覆盖审计执行失败，先修复证据或输入' }
if ($coverageExit -eq 2) { Write-Output '存在待核查项，停止签核并逐项处理' }
```

该扫描不读取 layout.json，不受 block 合并影响：按页面实际对象占用区扫描全部纵向空白带，再在每个内容带内扫描横向间隔。报告列出参与和排除的对象、全部测量值以及可能的文字错位。它不是全能的视觉识别器：重叠容器可能合并占用带，图片、原生图表、表格、组合图内部仍需局部核查；这些情况必须显式列为待检查项。
4. 核对所有排除对象的真实角色。只有真正背景可按背景处理，连线虽不参与模块间隙计算，仍检查其路径、方向、与文字距离和页面边距。标题/副标题的留白必须在全页视觉记录中核查，不能因不参与正文带统计而漏掉。
5. 遍历所有页的全部 findings；记录每项对应的图像和具体结果。数值差异若确由真实结构产生（例如封面分区），需用完整画面证明间距合理且不挤压其他内容；这不是一般豁免。用户已经指出的明显失衡不得用改分组、重新命名或“层级不同”驳回。实际失衡必须修复，重新测量和看图。

## 实际文字对齐

### 所有位置必做：坐标检查后再检查可见边缘

- **所有页面、所有位置都必须完成实际渲染的光学检查。** 覆盖标题/副标题、正文、编号、数字/单位、图表轴/图例/标签、表格、图标、图片/组合图内部、连线及页码。坐标相同、TextRange.BoundLeft/BoundTop 相同、落在数值容差内，都不能替代可见字形/图形边缘检查。
- 原因包括字形边距、字重、斜体、希腊字母/数学符号、字体回退、缩放和抗锯齿。先按坐标组织，再在当前真实 PNG 上看首尾可见笔画、视觉中心、基线及相邻空隙。对齐差异肉眼可见时修复，不以“小于2pt”作为放行理由。
- 自动扫描对可以分离的文字区域按多个对比度阈值估计实际笔画像素范围；稳定偏差达到 max(2px,0.75pt按画布比例换算) 时提出候选。这个阈值用于发现问题，不是低于它就自动合格。不得用整幅图的左边缘、透明边框或文本框空白代替文字笔画起点。
- **不同字号/字重/字体并列、标题与副标题并列或上下相邻、编号与小标题、数值与单位，强制增加局部视觉复查，即使自动像素测量稳定且无报警。** 根据语义核对真实首行基线、可见中心或共同左边缘，不把不同字高机械顶齐；尤其检查拉丁字母、希腊字母、中文、数学符号和粗体的首尾笔画。局部检查之后回到整页，确认这种补偿在正常尺寸下自然。`mixed_typography_optical_review` 不能因坐标相等而关闭，必须有局部证据和回整页记录。
- 背景复杂、渐变、阴影、文字重叠、图中位图文字、无法取得内部坐标或阈值测量不稳定时，列为局部视觉待核查；不得退回只看坐标后通过。放大局部定位后必须回到正常整页检查；必要时重新导出更高分辨率并交叉观察，区分真实错位与缩放噪声。
- 光学微调优先使用少量、可追溯的位置或内边距补偿，不改动图表数值和数据坐标。记录补偿前后的框坐标与实际像素边缘，防止自动对齐重新覆盖补偿。相同字号/字体/首字符模式复查同类组件；不要把一次D/λ的补偿量当作所有文本的固定偏移。
- `optical_text_inventory` 包含渲染报告全部文字，包括标题、页码及可识别的表格/组内文本；无法稳定测量的条目保持待视觉核查。`optical_review_targets` 包含全部顶层对象，排除于某个几何扫描的对象也在其中。图像、原生图表、表格及分组需要实际查看内部，不能因仅有一个顶层ID而省略子内容。

- 同行独立编号/图标标签与标题默认按实际可见文字垂直中心对齐，偏差不超过 2 pt；不能在检测失败后改称“顶对齐”来通过。正文多行与行名等需要首行基线时，在制作前明确这一关系并检查实际首行；用户明确指定其他对齐方式时遵从，并记录任务约束。框顶端一致不代表文字对齐；不同框高、内边距、垂直锚点和字体都可能使文字偏移。
- 使用渲染报告中的 bound_top_pt / bound_left_pt / bound_height_pt / bound_width_pt，核查真正文字边界。同行单行文字默认可见中心偏差不超过 2 pt（按页高缩放），同时看整页光学对齐；字体不同不能仅凭数值勉强过关。多行正文明确检查首行或整体中心，不能机械与短标签框顶对齐。
- coverage 的自动文字比较只覆盖能匹配到的部分单行相邻文本；未标记的文本、多行、图表及表格内部不是自动合格。必须逐行核查，尤其第一列行名与右侧所有列。

### 同列、跨栏及图表周边不能漏检

- 同一指标侧栏的标题、数值、说明默认共用可见左边缘；不能标题居中、数字左对齐、说明再缩进。需要整组居中时三者使用同一视觉中轴，制作前确定，不在告警后临时挑选最有利的锚点。
- 左图右文/左右图文各自内部合格后，还须比较两栏整体的可见顶端、底端与视觉中心。右侧多个指标以整组检查，不以每个文本框不越界代替两栏平衡。chart_sidebar_vertical_balance 是待修复/复核发现，不能只写“图文分栏不同”关闭。
- 图表按真实绘图区、坐标刻度/标签、图例和说明共同构成的可见范围测量；图表对象框、空白透明框并非最终依据。逐页同时记录标题区→图表可见内容，以及图表可见内容→总结两段间隙，默认差异不超过 max(3 pt, 两段均值的20%)，按页高缩放。若不合格，优先移动整组图表/说明、调整图表高度及轴标签间距，再渲染复查。不能只检查正文带内部而跳过上、下交界。
- 封面等没有“图表—总结”结构的页面，检查实际左右内容边界、标题到内容及内容到底边的构图关系，不伪造不存在的图表/总结。它仍需要全页证据，不是免检页。
- 标题下默认不追加解释性副标题。每条副标题在文稿阶段回答“删除后具体缺失哪个必要信息，是否已在主标题/图例/轴单位中表达”；重复主题、来源选材或泛化范围说明直接去除。日期、单位、估计属性在实际图表/指标中就地表达，不靠清除事实标记来制造简洁。

### 降低误报，但不能借误报取消检验

- 区分由数据决定的位置（柱高、气泡面积、散点坐标、分类轴位置）与由设计决定的位置（标题、侧栏数字、说明、编号）。前者不得为凑等距篡改数据；后者不能借“图表内部”免检。单个数据图发现误报不构成全页告警批量豁免。
- 数据坐标误报须绑定具体对象、源数据文件/哈希、坐标或面积公式与对应图像；“属于图表/不同语义”不是证据。数字编号不是数据坐标。数据点标签自身的避让、对齐、可读性仍须核对。

## 签核与退回

### 轴刻度与下方跨区说明

不能把真实纵轴刻度和图下整页结论合并成同一文字列。仅在实际结构同时满足以下条件时，扫描将它们分开：至少三个不同数值刻度与纵向位置构成线性映射；至少三根相邻无箭头水平网格线匹配刻度；下方文字覆盖页面宽度65%以上且位于整组刻度下方。该判断不依赖形状名字或作者自填的模块标签。

分开后仍检查刻度组自身的对齐，同时新增 `axis_stack_spanning_region_review`。必须提供 `axis_region_contract:{kind:linear_axis_and_spanning_text,axis_tick_ids:[全部刻度],matched_grid_ids:[全部匹配网格],spanning_text_id:下方文字ID}`，并查看当前局部图、回到整页确认真实关系。不得把结论写入数据位置豁免，也不得移动正确刻度来迁就误关联；普通标题—数字—说明组不满足上述轴结构时，继续整组检查。

- 签核记录绑定当前哈希、全页间距报告、覆盖扫描报告及逐项视觉处理记录。仅记录“逐页已看/横向pass/纵向pass”不够：每页列出最紧与最松间隙、同行文字对齐方式、未被自动覆盖的内部区域，以及结论条上下留白的结果。
- coverage exit 2 表示未完成验收，不能直接进入发布。必须先修复实际问题并重渲染复查；自动工具不能判定的项目需给出实际图像证据和具体观察。未处理/缺证据一律阻断，不能忽略退出码后填 signed_off。
- 用户或复核者发现问题时立即撤销该版本签核，保留原记录，不覆盖漏检历史。报告区分独立发现、用户发现、复核退回；扩查全稿同类布局，不只修被截图的位置。
- 本工具与规则减少漏检，不能证明 Agent 真实看过图片。禁止把自填布尔值、时间戳、文件存在或同一 Agent 的“已检查”当作独立证明；可追溯的版本、测量和图像用于复核，实际视觉判断仍是必要步骤。

### 签核前执行证据校验

#### 中间说明行的局部留白

图表外框常含无可见内容的白边。位于图表与结论条之间的独立说明，须从当前 PNG 的绘图区、刻度和图例整体最下可见像素，测到说明字形，再测到下方容器；不能从 Chart frame 底边算出“等距”就放行。所有这类图外关系（包括图片图表）均须局部＋整页复核；原生图表的高置信三对象结构由 `visible_chart_spacing.py` 独立发现并量化，即使 layout.json 没写或框距报告通过也会提出检查。框距与可见间隙分开保留，不能通过拆比较组、降低 minimum、重填 target 或删除原告警替代真实像素验证。工具字段及严格闭环见 [原始间距报告与可见图表边界](evidence-schema.md#原始间距报告与可见图表边界)。

表格/图表下的条件、提示、解释行是一个实际布局对象，必须同时测量它上方和下方的邻接间距。以真实字形上下边缘和相邻可见模块边界为准，不以文本框高度或大标题底边替代。无额外层级理由时，使两侧间距近似均衡；具体修复采用小幅上下平移，并检查是否挤压表格、结论和页码。全页标题区与这里不是必然同级：不能为修复全局header_body数值差，制造局部14pt/36pt等明显失衡。若两种检查互相冲突，回到实际相邻对象与语义层级复核，记录真实局部测量和整页观察；不得仅调JSON测量值，也不得把全页抽象间隔一律强制相等。

全量/增量范围统一执行 [签核范围判定](signoff-workflow.md#范围判定)。只有已全量签核后用户指出局部问题的修订才可增量；旧全稿记录保留原哈希，受影响页按相同标准重渲染及双遍检查，未变页须有 XML/关系/资源一致性证据。尚未全量通过的稿件不能自设局部例外。

**指标组全链检查。** 同一组标题→数值→单位→说明要共享一个可见左锚点、中轴或右锚点，默认统一布局；字号/字重/行数不同不降低要求。上部两项对齐不能掩盖下方说明偏移，单行与多行说明须同时核对。扫描独立合并紧凑混合锚点组，不信任作者手写分组。`different_alignment_roles` 只描述原生段落设置，不再直接构成放行理由：必须提供 `common_visual_anchor: left|center|right`，机器检查整组当前实际字形边界满足同一锚点。无共同锚点必须整组修复重渲染；真实不同模块可用已验证的结构契约，或通用独立视觉闭环证明；不强迫无色框混排新增容器。不能自称标题、数字和说明职责不同。像素提取不稳定或关系推断有误时必须局部＋整页独立复核；不能用坐标相同或角色名补写通过。

光学补偿造成COM文字边界不齐时，不得改回可见错位：`rendered_column_text_anchor_mismatch`可提供覆盖全部对象的 `alignment_contract:{anchor:left|center|right,shape_ids:[...]}`，校验器仅以重扫得到的当前PNG可靠字形边界验证同一共同锚点，阈值不放宽。不能提交自填像素坐标或只挑对齐的两项。此项还必须有当前局部证据、实际观察及整页复核；可靠像素不存在或仍偏移不能通过。

`text_region_relation_requires_review`若两者原生对齐方式相同，但文本内距/光学补偿使外框偏移，可用 `relation_contract:{kind:common_visual_anchor,common_visual_anchor:left|center|right,shape_ids:[全部ID],visible_relation_explanation:实际关系}`。它与混合对齐契约使用相同的整组可靠PNG字形验证和局部/整页证据门槛，不要求人为改变段落对齐类型或扩框来取得资格；共同字形锚点不成立即拒绝。

原生带文字的有色形状本身可以是真实容器：`separate_visible_containers`允许容器ID等于文字对象ID，但必须是实际不透明填色文字组件，各独立容器不能相互重叠；无填色文本框、透明代理和新加背景用于拆散原指标组均不成立。此契约用于原本真实独立的卡片/模块，不把同一指标的标题、数值、解释重新命名成三个模块。

图表侧栏候选要求整组至少一段文字与该图表纵向相交；完全位于图表下方的下一行标题不能误归上一行图的侧栏。真实侧栏仍按完整文字组检查，包括略伸出图表底部的解释，不能逐个排除偏下项来缩小失衡数值。

连接图同时执行 [连接完整性门槛](connector-integrity.md)。`connector_reviews` 自动对照原生连线清单，逐端核实目标、接触几何、当前局部像素证据及整页回看；通用 containment_and_connectors 描述不能替代逐根记录。短末段、回折、多段拼接、分支和交叉即使自动通过也强制放大视觉核验。缺项或端点失败向最终校验传导为非零，不能签核。

运行 `python scripts/verify_coverage_review.py candidate.pptx coverage.json coverage-review.json render-dir evidence-check.json`。非零则停止签核。旧的自由文本 disposition 不能冒充已通过此校验，需按下面结构重新整理并实际核查，不能只迁移字段或补写结论。

校验器会基于当前 PPTX 和该渲染目录的 audit.json 重新执行独立扫描，并与 coverage.json 完整比对；删除、修改告警列表或使用旧工具报告会被拒绝，不能靠手改 JSON 消除问题。

高敏感候选包括实际文字边界重叠、直线穿过/靠近文字、多行或混合字号同行关系、折线/曲线路径及不可取得的几何。包围框并非字形像素，可能误报；但不能静默跳过。碰撞和不明确的对齐不能以“数据坐标决定位置”关闭，必须修复或提供当前局部图证明不存在实际缺陷，并返回整页复查。

`coverage-review.json` 必须绑定最终 PPTX 哈希与 coverage 文件本身的 SHA-256，并且每个 finding 恰好一条：

```json
{
  "sha256": "PPTX_SHA256",
  "coverage_sha256": "COVERAGE_FILE_SHA256",
  "items": [{
    "finding_id": "报告中的实际ID",
    "decision": "verified_in_context",
    "image_sha256": "对应实际slide-NN.png的SHA256",
    "criterion": "本对象采用的具体检查标准与阈值",
    "object_relation": "具体对象及关系，不以角色名代替证据",
    "observation": "实际图像里看到的边界、关系与复查结果",
```

- 真实同行中心错位、同列锚点错位、跨栏失衡必须修正并重新扫描，不能以文字说明覆盖数值失败。图中数据位置确不构成版式对齐关系时，`object_relation` 为 `data-positioned labels`，另提供 `data_mapping` 的 path、sha256、formula、object_ids；校验文件存在与哈希只证明证据可追溯，执行者仍须核实映射内容和图像，禁止虚构文件骗过校验。
- 同列整组确实采用居中或右对齐时，可提供 `alignment_contract: {anchor: "center" 或 "right", shape_ids: [...]}`；必须包含该检查组全部对象，校验器直接检查整组实际中轴/右边界偏差不超过 2 pt，而不是接受自述。不能只挑两块对齐的文字，忽略第三块；同行大编号/小标题的中心检查不能借用此同列规则。
- `header_body_boundary_review` 的 measurements 必须有 `above_visual_gap_pt` 与 `below_visual_gap_pt`。真正独立封面可用 `standalone cover composition`，但必须提供 left_content_bounds_pt、right_content_bounds_pt、title_to_content_gap_pt、content_to_bottom_gap_pt，并实际检查；没有右栏时明确记录单栏实际范围，不能虚构。
- 校验返回 `evidence_complete_pending_visual_signoff` 仍不是发布许可。完整文本语义审查、全部页面与复杂局部实际查看、所有其他质量要求通过，才可最终签核。发现用户或复核者指出的未解决问题时，必须拒绝发布，不将“执行者已签核”当作优先依据。

碰撞/路径/多行对齐类发现需补充 `detail_evidence: {path, sha256, source_image_sha256}`、`returned_to_full_page: true`、`no_visible_collision_or_alignment_defect: true`，且 criterion/observation/measurements 必须说明为何实际画面没有缺陷；这些字段只能在真实检查后填写。误报说明不能复用到未检查的新页或新版本。

`coverage-review.json` 顶层还须有 `visual_passes` 两项，mode 分别为 `content` 与 `layout`，每项含最终 sha256 和完整 pages。每页记录 slide、实际 PNG 的 image_sha256、normal_size_viewed、result，以及 checks：

- content：readability、chart_semantics、language、quantity_unit_pairing（逐页核对数值与单位联排，包含图内与表格）。
- layout：row_alignment、column_alignment、whitespace、containment_and_connectors、page_number、rules_crosscheck、optical_edges。

每项 checks 填具体观察，不接受只有 pass/OK/不适用的占位；不存在某类对象时说明实际布局与已检查的替代关系。所有页面恰好各出现一次、哈希一致、结果通过才满足记录完整性。校验器只能检查一致性与证据完整性，不能证明执行者真的看过图；禁止提前批量生成通过记录。

版式遍每页另填 `rule_findings_reviewed`，恰好列出当前 coverage 报告中该页的全部 finding ID（确实没有才为空数组）。校验器对照重算后的报告检查漏项/重复/多项；rules_crosscheck 说明规则告警在图中的核查结果，以及视觉额外发现的处理情况。两遍完成后仍有任何疑点，继续迭代，不因记录结构齐全而签核。

版式遍每页同时填 `optical_targets_reviewed`，恰好包含该页 `optical_review_targets` 的全部 shape_id；optical_edges 记录实际笔画起点/中轴、图形边界及内部局部复查的观察。未核对全部对象、缺失局部证据或可见错位未解决，不能签核。对于 rendered_ink_column_misaligned / rendered_ink_row_misaligned，不能用COM文字边界一致来覆盖像素发现；若整组居中/右对齐成立，校验其真实笔画中轴/右边界，而非只填对齐方式。
