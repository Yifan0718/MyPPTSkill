# MyPPTSkill

**MyPPTSkill 发布版本：1.1** · [发布与更新日志](https://github.com/Yifan0718/MyPPTSkill/releases/tag/v1.1)

本目录的 `VERSION`、`manifest.json` 与 `updates.json` 记录上游模板 Skill 的更新基线，供自适应更新使用；MyPPTSkill 的发布版本由仓库根目录 `VERSION` 和 GitHub Release 标识。

## TL;DR

**复杂 PPT，讲得漂亮，排得整齐。**

充分发挥多模态 AI 的视觉能力，不靠一遍直出：逐页看图、反复核验细节、修正后再检查，尽最大努力把排版打磨到完美。

- **摆脱 AI 味**：去掉免责声明、空洞套话、长篇赘述和小字堆砌，让表达自然、清楚、有判断。
- **告别排版错乱**：溢出、遮挡、挤压和悬空箭头，逐项找出、修正到位。
- **强迫症级对齐与统一**：从字形起点到图表边界，从横纵间距到跨页风格，细节逐一打磨。
- **复杂内容照样好看**：多图表、代码、公式和科研图文混排，兼顾信息密度与可读性。
- **你的规则，持续有效**：持续跟进上游 GordenPPTSkill 更新，自适应保留已固化的定制规则与修复。

MyPPTSkill 是 [GordenSun/GordenPPTSkill](https://github.com/GordenSun/GordenPPTSkill) 的定制 fork，提供 21 套中文模板，支持模板编辑、原创设计与复杂图文混排。

## 安装与使用

将 `my-ppt-skill` 整个文件夹安装到工具的 Skills 目录。Codex 默认使用 `~/.codex/skills/`；配置了 `CODEX_HOME` 时使用其对应的 Skills 目录。不能只复制 SKILL.md：脚本、参考规范、模板及更新保护注册表需要一起保留。

显示名称为 **MyPPTSkill**，调用标识为 **`$my-ppt-skill`**。例如：

```text
使用 $my-ppt-skill 制作 MATLAB tiledlayout 教学 PPT。
6 页，含独立封面；作者“示例作者”；使用数据可视化模板。
包含可运行源码与实际生成的图，逐页检查后交付 PPTX 和 PDF。
```

支持内置模板、用户自带 PPTX 模板、完全原创三种模式。编辑用户模板时使用工作副本，不覆盖原文件。

- 没有明确封面或页数时先询问；已经提供的信息不重复问。
- 大纲有实质歧义时提供组织方案，目标清楚时直接推进。
- 用户指定模板直接使用；需用户选模板时通常展示三套真实第一页预览，剩余候选不足三套时如实展示，有更多候选时提供换一批。
- 默认总页数包含封面。不为满足字号或留白机械拆页，不擅自突破页数上限。
- 作者根据明确提供的信息或页面真实署名填写，不拿引用作者、公司或软件名代替。

## 开发与测试环境

本项目开发与测试使用 **GPT6-Astra** 模型，配合官方 **ChatGPT Desktop（Codex）Harness** 完成工具调用、迭代与验收。

实际使用时，建议选择**长程思维能力和多模态能力都较强的高级模型**：任务需要持续跟踪约束、理解复杂图表与代码、观察真实渲染、定位细微版式问题，并在多轮修改后保持内容与证据一致。执行环境还需要支持本地文件、脚本、图像查看及相应渲染工具。

可选用具备上述能力的模型与 Harness；每个任务均按统一流程完成规则检查与逐页视觉验收。

## 环境要求

| 能力 | 要求与处理 |
|---|---|
| PPTX 构建和审计 | Python；依赖包括 python-pptx、Pillow、lxml，其他依赖按所用工具检测。优先使用已有运行时 |
| Windows 渲染 | 优先使用已安装的桌面 PowerPoint 和 PowerShell；默认后台无窗口运行 |
| 其他渲染 | 可用 LibreOffice／Poppler 等实际渲染，签核同时提交对象、字体、PNG及配套审计证据 |
| 科学图 | 按需调用已安装的 Python／Matplotlib、MATLAB、LaTeX、R、Julia、Octave、Graphviz 等；Windows 同时考虑已有 WSL |
| 字体 | 检查可用中文／英文字体，代码可采用 Consolas 等宽字体；字体替换后重新渲染检查 |

可选工具不可用时选择可用工具，不自动安装或激活软件，不假称已执行。不同渲染器可能产生不同布局，必须检查实际交付环境的结果。详见[科学绘图工具规范](references/scientific-visualization.md)。

## 默认交付要求

| 项目 | 默认行为 |
|---|---|
| 内容 | 事实扎实、证据与结论对应；不写制作流程、验收自述或泛化防御句；保留日期、估计、模拟等真实属性 |
| 叙事 | [发布会原则](references/narrative-reference.md)按用途选用，客观比较和学术材料不强行宣传，不藏关键反证、不换口径制造优势 |
| 标题 | 直接表达主题或判断；不强加无意义副标题；标题区紧凑，不能挤压主体 |
| 页尾 | 只保留 x/y 页码；封面也编号，每页一个，全稿位置一致，至少 3 pt 隔离 |
| 常规字号 | 标准 13.3333×7.5 英寸页面至少 12 pt；正文通常 14–18 pt，页标题建议 26–32 pt，短标题建议 16–22 pt；页码可 10 pt |
| 特殊字号 | 普通表格困难时可 10 pt；图内辅助文字按 12／10／8 pt 分级。8 pt 仅限必要复杂技术图局部，不能用于正文、普通表格或代码正文 |
| 8 pt 证据 | 先实际渲染 10 pt、定位冲突并尝试布局调整；说明保留必要性和不能合理拆图的原因；逐项绑定最终对象和签核 |
| 外边距 | 标准页面左、右、底部至少 0.35 英寸，建议约 0.44 英寸；其他画布按高度同比缩放 |
| 模块与容器 | 同级独立模块间隙默认至少 12 pt，目标容差 max(3 pt, 20%)；有色容器检查实际可见内容的四边留白 |
| 复杂内容 | 按内容组合多图表、图标、代码和公式；数字与单位尽量不拆行；原生可编辑对象优先，科研图保留实际来源和可复现素材 |
| 文件属性 | 只清生成程序身份，保留其他正常属性；作者有依据才填写 |
| 文件外壳 | 缩略图为实际第一页 JPEG，模板预览也来自真实首图；保存普通视图，后台准备与渲染 |

数值是对应画布和对象类型的默认值，不要求不同层级的间距绝对相同。可见失衡不能因坐标容差内而放行；数值与真实视觉不一致时走独立复核流程。

## 从制作到签核

1. 确认需求、选模板、检查更新；记录本次规则和素材版本。
2. 确定表达档位与章节导航；逐页安排论证职责，按代表性与论证任务选择案例，统一页面网格和对齐锚点。
3. 构建候选，检查文字、数据、字体和元数据；准备首图缩略图和普通视图。
4. 从稳定快照实际渲染全稿，执行间距、覆盖、连接、语言和证据检查。
5. 每页分别做内容遍和版式遍；按首次阅读视角复述，检查术语、操作、指标及证据。复杂区域放大查看，再回到正常整页，并核对跨页一致性与色调。
6. 修正后重新渲染复查，必要时多轮迭代；不为凑轮次制造无意义修改。
7. 通过 `verify_delivery.py` 汇总版式与首次阅读证据；问题全部关闭、证据与候选一致后实际签核，核对交付文件哈希，再交付成品。

首次签核必须覆盖全稿。仅已全量签核后用户指出局部问题的修订，才可凭影响范围证据复验全部受影响页；共享资源、页数或规则变化可能要求重新全量检查。

### 规则不通过时如何继续

对于间距、对齐或对象关系误报，保留原始告警、阈值和数值，查看当前局部与整页，并由另一位实际复核者确认。视觉确实合格时关闭对应版式拦截，继续其余验收；作者不能自授免检。

缺页、旧哈希、执行异常、虚构数据、未满足字号例外证据等必须实际修复，不属于视觉兜底范围。工具故障保留失败记录，采用可验证的恢复或替代路径，不直接停工，也不拿残留图片冒充完整渲染。全部待复核项关闭后才能签核发布。

## 更新与额外要求保护

以下命令在 Skill 根目录执行。首次使用执行 `python scripts/check_update.py`。失败须如实记录，可继续使用已安装的有效版本，但不能声称已是最新。

```text
python scripts/apply_update.py prepare --stage <新的暂存目录>
python scripts/apply_update.py apply --stage <同一个暂存目录>
```

两条命令之间必须审查差异、完成 `review.json`；不能无条件串联。

- 暂存时根据上游基线和注册表发现已有修改、未来新增要求及删除路径，保存本地快照。
- 明显冲突列出双方内容并显式向用户确认；不冲突的更新审查后继续。
- 暂存后本地要求、候选或保护注册表变化，则旧计划失效，重新暂存。
- 受保护文件保持原字节，已删除项不复活；吸收上游改进需另行审查合并。
- 失败非零传递，应用失败回滚；回滚失败先恢复安装，不使用半更新状态。
- 保护注册表采用临时文件写入后原子替换，避免中途写坏；最终结果记录失败也进入回滚，Ctrl+C 中断会尽力恢复并返回非零。Git 调用限制等待时间且不进入交互式凭证提示；超时可修复网络后重试，或使用已审查的本地候选目录。
- 新上游模板先清理缩略图和视图；未验证的 preview 不直接展示。开发测试和脚本目录 PPTX 夹具不会重新混入发布安装版；已受保护的用户文件优先保留。

`VERSION`、`updates.json`、`manifest.json` 是上游基线和机器更新依赖，不是普通修订日志。`local-overrides/registry.json` 保存保护路径及删除标记，不能清空或用上游清单替代。

只有用户明确要求修改 Skill、固化规则或设为长期默认值时才修改安装版；普通单稿反馈只影响当前任务。更新／修复后重新冻结版本，不边改规则边签核。

最终证据命令：`python scripts/verify_delivery.py candidate.pptx coverage.json coverage-review.json render audience-review.json delivery-check.json`。记录字段及异常处理见[证据接口](references/evidence-schema.md#首次阅读与反馈证据)。内容准备任务按其阶段执行，正式成品完整执行渲染与签核。

准备和渲染使用[有界执行](references/signoff-workflow.md#有界执行与报告写入恢复)，卡住时可定位、换目录重试或切换工具。审计报告原子写入，路径检查保护输入与原始证据；超时及失败运行保留可恢复状态。
